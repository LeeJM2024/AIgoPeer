# AlgoPeer 演示材料交付清单与完整操作链路

确认日期：2026-10-28。

本文记录已确认的演示准备范围、材料交付内容、角色操作顺序和录屏安排，作为后续准备、彩排与正式录制的执行依据。本文是计划清单，不代表材料已经生成或演示已经执行。

## 一、演示目标与边界

演示主线：

**教师布置 → 学生完成 → 跨班匿名评审 → 教师复核发布 → 学生查看反馈 → 教师分析教学情况。**

1. 重点展示平台功能，学生作业材料简单、完整、可运行即可，不制作高规格教学课程。
2. 学生期末作业选题以用户提供的 26 个正式选题为准。所属大章节和知识点选择由另一个 Agent 实现，本项材料准备不改动该部分代码。
3. 学生上传材料先交给用户，由用户亲自登录学生端、认领选题并上传，不提前代为上传或写入学生提交记录。
4. 参与数据使用合成学生身份，不展示真实同学隐私。作品内部不放姓名、学号等身份线索，外层 ZIP 按系统要求命名。
5. 正式演示走正常业务流程：等待真实截止、通过实际材料检查、生成真实评审任务、收齐有效评分后聚合与发布。
6. 正常与 HIGH 风险场景使用不同作品。历史关系异常使用不同作业积累的实际记录，不以重复聚合同一作业凑支持次数。

## 二、需交付的演示材料

| 编号 | 交付物 | 内容与用途 |
| --- | --- | --- |
| M01 | 学生期末作业完整 ZIP | 简单 PPT、短讲解视频 MP4、C++17 源码、README、至少三组测试输入与预期输出，用于用户亲自上传 |
| M02 | 学生期末作业缺材料 ZIP | 从完整包中去掉视频，演示检查失败、修正材料与重新上传 |
| M03 | 上传填写清单 | 对应账号的外层 ZIP 文件名、认领知识点编号、包内文件路径、例题页码、测试路径 |

| M06 | 教师配置与评分清单 | 作业配置、Rubric、教师初评分、评审分数与评语、正常及异常场景、教师复核理由 |
| M07 | 演示角色与操作清单 | 账号、所属班级、负责步骤、作业编号、提交编号、评审任务编号；实际生成后补齐编号 |
| M08 | 完整录屏脚本 | 页面操作顺序、角色切换、讲解词、预期结果、章节字幕和录制检查点 |
| M09 | 验收检查表与证据清单 | 各功能通过情况、截图与导出位置、问题及处理结果 |

### 2.1 学生上传包的简单内容标准

- PPT：讲清题目、算法思想、简单过程、正确性要点、时间与空间复杂度，并含至少三个可定位的例题。
- 视频：与 PPT 对应的短讲解，包含实际内容，不使用纯色静音占位片段。
- 源码：可编译运行，内容与所选主题及测试对应。
- 测试：至少三组输入与预期输出，文件路径与页面清单一致。
- README：简单说明文件结构、编译运行方式和例题。
- 允许多份作品复用简单模板，按选题调整标题、内容或例题，不要求为每名学生制作精品课程。

建议采用便于填写的包内结构；实际材料生成后，以交付清单中的路径为准：

```text
slides.pptx
video.mp4
README.md
src/main.cpp
tests/1.in
tests/1.out
tests/2.in
tests/2.out
tests/3.in
tests/3.out
```

外层 ZIP 按实际账号与已认领知识点命名：`学号_姓名_知识点编号.zip`。例题页码须填写真实页码，不固定照抄模板数字。缺视频版本与完整版本放在不同文件夹，供同一账号先后上传。

### 2.2 两种视频的区别

1. **学生讲解视频**：放进学生 ZIP，供上传、匿名评审和材料预览使用。
2. **平台完整演示视频**：录制教师、学生、学生评委的页面操作，是最终展示系统功能的成片。

## 三、参与规模与角色准备

建议采用一位教师、两个班各 12 名学生，共 24 名学生。

对一轮期末作业，在 24 人均符合有效参与条件且各提交一份作品时：

- 共 24 份作品、120 条初始评审任务。
- 每份作品由五名不同评委评阅。
- 两班人数相等时，每名学生初始承担五份评审任务。
- 严格跨班，禁止本轮直接互评，初始班内负载均衡。
- 相比 10＋10 的最小均衡规模，12＋12 为补评候选留出更多配对空间；具体替补任务与候选人在彩排中验证。

120 条任务仅指这一轮期末作业，不是所有主观作业和历史作业的总量。其他作业按实际演示场景另行准备。

| 角色 | 主要职责 |
| --- | --- |
| 教师 | 配置课程、发布作业、确认分配、查看过程、替补缺评、初评锁分、聚合复核、发布、分析与导出 |
| 学生作者 | 完成编程题、在线作答、认领并上传期末作品、查看历史和最终反馈 |
| 学生评委 | 使用同一个学生身份进入评审任务，阅读匿名作品、按量表评分并填写意见；不是独立的教师账号 |

教师与不同学生建议使用独立浏览器会话，切换时核对当前身份。完整验收覆盖全体参与记录，正式录像跟拍代表账号和关键步骤，不录制全部重复填表过程。

## 四、完整操作链路

### 阶段 1：教师准备课程与作业

教师操作：

1. 登录，进入教师工作台。
2. 查看两个班级及学生名单，演示一次新增或导入学生。
3. 查看知识点目录，确认 26 个选题及章节信息就绪。
4. 创建编程作业，配置题面、输入输出、公开与隐藏测试、时间和内存限制、截止时间。
5. 创建期末作业，配置关联班级、Rubric 和提交／评审截止时间。
6. 创建算法分析题、证明题、开放题，填写题面与评分标准。
7. 检查草稿并发布，切换学生端确认可见。

验收重点：教师配置保存正确，发布前后状态清楚，学生只看到其所属班级可见的作业；编程隐藏测试不在学生题面泄露。

录屏安排：完整配置一份代表作业，其余题型展示关键差异，减少重复表单镜头。

### 阶段 2：学生完成编程题

学生操作：

1. 查看作业列表、题面、公开样例和截止时间。
2. 提交错误代码，查看判题状态和反馈。
3. 修改代码，提交正确版本，取得 AC。
4. 查看运行时间、内存和用例通过情况。
5. 查看历史提交，打开旧版源码与错误记录。

验收重点：AC、WA、CE、RE、TLE 分别用对应代码检查；排队和运行状态最终更新，旧提交可追溯。

录屏安排：重点跟拍“错误 → 修改 → AC”，其他结果集中展示。

### 阶段 3：学生完成在线主观题

学生操作：

1. 打开算法分析题、证明题或开放题，阅读题面。
2. 在线填写并提交答案。
3. 修改答案再次提交，形成新版本。
4. 查看当前答案和历史版本。

验收重点：三种题型都检查；答案与作业对应，当前版和历史版区分明确，不覆盖旧记录。

录屏安排：完整操作其中一种，另外两种展示实际页面及提交结果。

### 阶段 4：学生亲自认领并上传期末作品

由用户亲自操作学生页面：

1. 打开期末作业，阅读提交要求。
2. 选择所属大章节，再选择知识点并确认认领。
3. 选择缺视频 ZIP，填写包内材料路径、例题页码、测试路径并上传。
4. 查看材料检查未通过，以及缺视频提示。
5. 改传完整 ZIP，查看材料检查通过。
6. 查看当前版本及历史上传记录。
7. 其他参与账号完成各自的认领、上传与有效材料检查，为本轮分配准备完整参与集合。

验收重点：认领结果和文件命名一致；上传错误有具体反馈；重新提交形成新版本；通过完整性检查与作品内容评分分开。

本阶段不由助手提前代传，不直接写入提交记录。

### 阶段 5：教师初始化跨班评审

前提：提交已自然截止，参与作品符合实际资格和材料条件。

教师操作：

1. 打开评审分配预览。
2. 核对两班有效参与者、作品数量、预计评审工作量。
3. 确认预览，执行跨班随机分配。
4. 查看生成的任务与负载结果。
5. 说明每份五评、严格跨班、班内负载均衡和禁止本轮直接互评。

验收重点：任务由算法分配，不是自由领取或手选固定五人；预览名单变化后需重新确认；不能重复初始化生成重复任务。

### 阶段 6：学生作为评委完成匿名评审

学生评委操作：

1. 进入评审任务页，查看本人被分配的任务。
2. 打开一份匿名作品。
3. 对期末作品下载匿名材料并开始评审；对在线主观题查看匿名答案。
4. 阅读 PPT、视频、源码或答案。
5. 按全部 Rubric 项目填写分数，填写具体文字意见。
6. 提交评分，查看任务完成状态。
7. 展示已提交评分不能随意覆盖。

验收重点：仅能访问自己的有效任务；匿名材料不暴露作者身份；评分项与评语完整；提交后状态正确。

录屏安排：完整操作一份评审；其余评审在准备或彩排中按正常流程完成，不逐条录制重复动作。

### 阶段 7：教师处理缺评并替补

提前保留一份未完成的评审任务。

1. 教师查看缺评状态，展示该作品评分未齐，正式聚合及发布仍有阻断。
2. 教师填写原因，替补未完成任务。
3. 原评委不再拥有该有效任务，新评委看到接替任务。
4. 新评委阅读材料并完成评分。
5. 教师查看原任务、替补任务和原因记录，确认作品收齐五份有效评分。

验收重点：已提交评分不可替补；替补记录可追溯；不通过跳过检查解决缺评。替补后的实际负载与初始均衡结果分别理解和展示。

### 阶段 8：教师初评、聚合与异常复核

教师操作：

1. 查看作品，按量表完成教师初评并锁定。
2. 五份有效完整评分齐备后，执行聚合。
3. 查看五人原始分、聚合结果、区间及风险证据。
4. 展示一份正常作品，说明普通路径使用教师 60%、评审聚合 40%。
5. 打开另一份异常作品，查看实际触发的分数、行为或历史关系证据。
6. 按页面要求显式处理 LOW／MEDIUM 提示。
7. 对 HIGH 作品，由初次评分的同一位教师查看第一次教师分、五人分、聚合分与异常证据，填写一个最终分及理由。

验收重点：正常与 HIGH 是不同作品；算法不改写教师初评；HIGH 路径最终分来自教师复核，不再按普通 60/40 混合。

历史场景准备：

- 单次离群或行为异常可在当轮展示。
- 重复同向关系需要至少三个不同作业的支持，包含当前作业；不能靠同一作业重算累计。
- 多轮记录通过正常流程提前准备，并在彩排中核对算法实际命中的证据；录屏打开历史证据，不重复播放每轮全部提交过程。
- 分配减少历史重复，因此历史案例需提前验证实际配对与支持条件，不在录屏现场临时假定一定命中。

### 阶段 9：教师发布，学生查看反馈

教师操作：

1. 执行发布前检查。
2. 确认五评齐备、教师分锁定、异常处理及必要复核完成。
3. 正式发布成绩。

学生操作：

1. 发布前查看未公布状态。
2. 发布后查看本人最终成绩、评分标准、匿名评语和教师反馈。
3. 阅读修改建议。
4. 切换另一名学生，展示其本人结果，与前一个账号区分。

验收重点：发布前不提前泄露最终结果；发布后只读本人反馈，不展示其他学生成绩或教师内部风险证据。

### 阶段 10：教师分析教学情况并导出

教师操作：

1. 查看班级成绩分布及主观题结果。
2. 查看编程通过率、提交次数和常见错误。
3. 查看学生的完整编程提交历史。
4. 查看描述性题目难度和知识点观察掌握情况。
5. 切换班级或筛选条件，观察结果变化。
6. 导出成绩，打开导出文件，展示成绩及来源信息。

验收重点：统计能与实际提交和已发布成绩对应，筛选有效，导出文件可打开、内容与页面一致。

### 阶段 11：说明核心算法与实验成果

用约两至三分钟展示已有实验输出：

- 联合约束分配：跨班、五评、均衡负载和禁止直接互评如何共同满足。
- 稀疏贝叶斯聚合：作品潜在分、评委严宽偏差、可靠性，以及少量样本时的先验策略。
- 异常检测：单轮评分与行为证据如何结合历史关系进入教师复核。
- 规模及对照实验：展示已有 100∶40、120∶40 等场景的真实输出、耗时与聚合误差对照。

页面演示采用便于跟随的 24 人规模，算法规模能力通过已有实验结果补充。实验图表使用实际结果，与课堂演示数据分开说明。

## 五、准备、彩排与录制顺序

1. **材料交付**：先交学生 ZIP、编程与主观题资料、教师配置清单、账号操作表。
2. **环境及版本核对**：确认其他 Agent 的页面改动已就绪，核对当前代码版本、数据库迁移、前后端、材料处理和判题服务。
3. **用户亲自上传**：按角色清单完成认领和上传；代表账号录制缺材料纠错与版本历史。
4. **按阶段准备数据**：通过正常流程完成其他学生提交、必要的历史作业及大部分评分。除上传外的批量准备方式开始前另行确认。
5. **完整彩排**：按本文逐项检查，将实际作业、提交和任务编号补入脚本，记录并解决问题。
6. **正式录制**：跟拍关键角色和操作，保存未剪辑片段、截图及导出文件。
7. **整理成片与验收证据**：加章节字幕，剪去重复填表和真实等待，保存最终验收记录。

## 六、录屏结构

建议成片约 20～25 分钟，按实际操作速度调整：

| 章节 | 主要内容 |
| --- | --- |
| 课程与布置 | 教师工作台、名单、知识点、题目与作业发布 |
| 学生完成 | 编程判题、在线作答、期末认领上传、错误纠正与历史 |
| 公平评审 | 名单预览、随机分配、匿名材料、量表评分、缺评替补 |
| 教师决策 | 初评锁定、聚合结果、风险证据、最终复核与发布 |
| 教学闭环 | 学生查分与建议、教师学习分析、成绩导出 |
| 算法总结 | 核心设计、复杂度和已有实验结果 |

提交和评审存在时间条件，采用分段录制：先录提交，等待自然截止，再录分配和评审，条件完成后录发布。用“提交截止后”等字幕说明时间推进。主线尽量贯穿同一份期末作业；展示历史作业或不同场景时明确切换对象。

| 待填写 | 待填写 | 待填写 | 待填写 | 通过／失败／未执行 | 待填写 |

结束时保存导出、截图和录屏，退出演示账号，保留演示数据供追溯。本文不授权删除已有数据、绕过业务约束或改动其他 Agent 正在处理的功能。
