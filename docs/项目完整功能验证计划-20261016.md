### 2.2 证据标签

| 标签 | 含义 | 能证明什么 |
| --- | --- | --- |
| U | 纯函数/组件自动测试 | 算法不变量、状态分支、组件交互；记录替身 |
| I | 独立 PostgreSQL 集成测试 | 真实迁移、事务、约束、持久化；认证覆盖或依赖替换须说明 |
| A | 对运行服务的 HTTP 检查 | 真实认证、接口、对象归属；记录请求、响应及对象 ID |
| B | 真实浏览器检查 | 用户可实际完成操作、页面反馈和状态一致 |
| J | 真实 worker/Redis/Docker 判题 | 代码经过实际队列与隔离容器执行 |
| V | 真实 ffmpeg 与匿名派生材料 | 视频实际可处理、派生包可读取及材料权限 |
| D | 数据库只读核验或事务内拒绝检查 | 计数、版本、快照、不变量、触发器；使用专用验证对象 |
| R | 配置、运行清单与证据审阅 | 版本、隔离归属、证据层级与报告一致性；不能替代运行验证 |

矩阵中以 `+` 连接的标签均须取得；`U/I` 表示可按该分支采用纯函数或集成测试，具体选择必须在执行记录中写明。不能用同一层证据替代另一层，例如构建通过不能替代 B，复制 MP4 的替身不能替代 V。

所有范围条目均为必查。一个条目包含多个变体时，执行记录拆分为子例，如 `C01-01.a`、`.b`；全部必需子例完成后父项才能 PASS。不存在“整份测试文件通过，因此同组所有边界通过”的推断。

## 5. 验证环境的具体设计

### 5.1 三个数据区

| 区域 | 用途 | 生命周期与限制 |
| --- | --- | --- |
| AUTO | pytest 专用 PostgreSQL 空库 | 每个测试临时 schema；不接浏览器业务、不执行业务 seed、不预先在 public 迁移 |
| FLOW | 运行前后端、Redis、worker、存储，供真实闭环 | 独立 Compose 项目/网络/卷、账号与密钥，材料和结果持久保留到复验结束 |
| FAULT | 可抛弃故障试验区 | 用于 Redis/Docker 故障和恢复等会中断服务的场景；不停止 FLOW 和旧 QA 服务 |

AUTO 可与 FLOW 使用同一**新建的验证 PostgreSQL 实例**，但数据库、登录角色、权限分别隔离；业务角色不得访问 AUTO。FAULT 独立队列和存储，涉及停库时使用独立实例。

不复用现有 QA/业务库、旧卷或 `.env`，不执行 `docker compose down -v`、全局 prune 或业务数据清理。证据使用仓库已有忽略目录 `tmp/verification/<run-id>/`，验证材料放在其 `fixtures/`，避免提交大型 ZIP/MP4 或凭据。

后续执行入口示意（在上述文件已准备并通过 ENV 检查后）：

```powershell
# 当前工作目录：仓库根目录。路径及名称从本轮运行清单读取。
$verifyRoot = (Resolve-Path '.\tmp\verification\<run-id>').Path
$verifyCompose = Join-Path $verifyRoot 'compose.verify.yml'
$verifyEnvFile = Join-Path $verifyRoot '.env.verify'
$verifyProject = 'algopeer-verify-<unique-id>'
docker compose --project-name $verifyProject --env-file $verifyEnvFile -f $verifyCompose up -d --build
docker compose --project-name $verifyProject --env-file $verifyEnvFile -f $verifyCompose ps
Invoke-RestMethod 'http://127.0.0.1:18000/api/health'
# 前端使用单独终端及本轮基线 frontend 目录：
Set-Location -LiteralPath '.\frontend'
$env:API_PROXY_TARGET = 'http://127.0.0.1:18000'
npm run dev -- --host 127.0.0.1 --port 15173 --strictPort
```

`<...>` 均为执行前要替换的占位值，端口以清单实际值为准。Compose 启动时通过既有 Alembic 迁移建立 FLOW 结构；AUTO 不走该启动迁移。Docker Desktop 不可用、镜像构建失败或 ffmpeg 不可用均记 ENV 阻塞，不能用模拟结果签收 J/V。

专用空 FLOW 通过受审查的一次性初始化程序建立 T1/T2 教师身份，程序只接收本轮连接与本轮命名前缀，不改 schema，不创建预填成绩。可参考 `seed_demo.py` 的密码生成方式，但不把其无真实材料的评分阶段数据当成验收数据。

教师分为零、满分、合法小数、非法精度、非 100 满分分别设置子例。统计所需不及格/及格/满分等合法结果可复用上述作业；若既有结果未覆盖分布分支，另建小型独立作业，不修改已发布成绩。

### 6.3 期末材料

每个真实作品使用实际有效 PPTX（建议 8 页，例题在 2/3/4 页）、短 MP4（如 10—20 秒，仅用于处理链路，不冒充时长合规）、README、C++ 源码、三组输入/输出。ZIP 命名遵守 `学号_姓名_知识点编号.zip`，清单与真实路径一一对应。

合成材料正文不含身份；PPT 属性/视频元数据放可辨认的合成标记供清理验证；可见文字/音频的人工匿名核查单独记录。制作有效包、缺视频、缺 README、错误页码、清单缺项、身份线索、坏视频等变体并记录 SHA-256。

危险 ZIP（穿越、绝对路径、符号链接、重复条目、异常压缩比等）使用有界小样本；超限分支优先采用精确大小的可控请求或 AUTO 边界夹具，不制造真实压缩炸弹。无法实际验证某资源上限时，记录该分支未验证，不能以小样本拒绝推断全部上限通过。

匿名包检查：列出所有条目并对照清单、检查通用名称和支持格式元数据、搜索合成身份标记，抽查 PPT/视频实际可打开，确认未声明条目未泄露。教师原件可访问与评审派生包可访问分别取证。

### 6.4 判题样本与独立预期

两数求和隐藏用例至少包含非零和、负数和零边界，数值范围明确不引起 C++ 溢出。正确样本由输入独立手算输出，不读取判题结果来反推期望。

| 样本 | 内容 | 预期 |
| --- | --- | --- |
| AC | 读取两个整数并输出和 | 真实容器 AC；通过数与实际用例数一致 |
| WA | 固定输出 0，隐藏用例含非零和 | WA |
| CE | 明确语法错误 | CE；仅允许的受限编译信息 |
| RE | `std::abort()`，包含 `<cstdlib>` | RE |
| TLE | 持续无限循环 | TLE，容器有界结束 |
| OUTPUT | 正确输出加尾随空白；另例有前导差异或额外内容 | 按现有输出归一化契约区分，不泛化为“忽略所有空白” |
| INFRA | FAULT 中连接失败/执行等待超时/服务恢复 | 按队列和 worker 现有重试、终态规则核对，不将排队等待一律判为 SYSTEM_ERROR |

队列等待和 RUNNING 可能很短，采用服务日志、数据库状态转换或短时停留在专用 FAULT worker 捕捉，不为了看到动画伪造状态。记录执行前后的容器、提交、队列标识，确认结果不是旧提交的缓存。

### 6.5 算法、风险与成绩的判据

1. FINAL-SMALL 提供精确手算锚点：逐项中位数 85、`learned=False`；正常行为下不因回退区间宽进入 HIGH；教师 90 最终为 88，来源 NORMAL_BLEND。回退区间不据此宣称已学习。
2. FINAL-NON100 的五人逐项一致结果为 31/40，教师 34/40，`0.60×34+0.40×31=32.80`；由独立 Decimal 计算核对，不能调用生产计算函数生成预期。
3. 正式多作品样本：MAIN 的 A 班 3 份评分分别采用五人一致 72/80/88，B 班分别 80（其中 B01 的一名评审给 10）、70/90；单项满分 100。长评语且下载后等待至少 120 秒以上再提交正常评分，建议 300 秒，以真实服务端耗时为准。先集中下载后共同等待，避免逐任务等待。
4. B01 的四人 80、一人 10 应触发 FOUR_VS_ONE_OUTLIER；记录异常人、跨度和偏离。教师初评与复核最终分独立保留，例如初评 90、复核 87，最终必须直接为 87。
5. MAIN 的其他作品不预先承诺绝无 HIGH：记录真实风险；若与独立规则预期不符先分析缺陷/数据条件，不能降低阈值或直接清除异常。所有实际 LOW/MEDIUM 显式处理、HIGH 按真实教师流程复核后才能发布。
6. 另设行为样本：正常耗时但短评语（孤立信号）、短耗时加短评语（组合信号）、三维低熵、教师与聚合显著不同。预期从规格阈值及实际输入计算，不把“总风险为 LOW”等同于“没有待处理异常”。
7. AUTO 覆盖 1/2/3 份不同作品、稀疏评审人、重复/缺项/满分不一致、逐作品一致豁免、四对一及行为保留、未收敛恢复先验与 FAILED 持久化、配置/版本/输入哈希复用及历史归档。
8. 风险阈值需覆盖阈值下/等于/上：跨度 .15、偏离 .30、后验 .95、模型与中位数差 .15、区间宽 .20；行为阈值 120 秒及 Panel 中位时长的 .25、评语去空白 30 字、熵 .20、至少 3 个 Rubric。不能从零散已有测试推断边界均已覆盖。难以通过完整模型精准构造的数值，用受控 U/I 输入验证规则，明确证据层级。
9. Bayesian 多作品聚合不使用规格中的近似例值 35.2 作为精确金标准。用独立中位数、归一化、约束、偏差中心化、有限/合法范围、可重复性及风险公式核对；确需特定数值容差时先按规格建立独立参考或由成员 3 给出可审阅推导，不能仅以同一个函数调用两次证明正确。
10. 公布分数独立采用 Decimal、保留两位、ROUND_HALF_UP，与数据库 NUMERIC 和页面/导出核对。逐个作品核对教师版本、聚合运行、复核分及来源，而非只检查平均数。

### 6.6 截止与并发

主线作业发布前根据实际准备情况设置足够的未来提交/评审窗口；人工主线建议预留至少 60 分钟上传、至少 120 分钟评审，若预检显示不足，在**发布前**增加。准备材料和账号完成后再创建并启动主线时间窗口。

短截止专用作业可设置发布后 2—5 分钟；在开放时真实提交，等待自然截止后核验只读。跨截止收包、精确临界点、竞态和旧状态兼容使用 AUTO 的受控时钟/夹具补足；不修改已冻结的 FLOW 作业来重演上传，不改宿主系统时间。评审不足只走合法延期或新建作业。

并发子例使用两个独立客户端会话与同步起跑点；记录所有响应及数据库最终计数，不能仅看其中一个成功请求。涉及保存/锁定/更正/发布的竞态遵守业务合法版本关系，预期为成功一次或明确冲突且历史完整，不写死任意并发请求必须按某一顺序返回。

## 8. 真实闭环的执行顺序

### 8.1 C01—C04：注册、发布与编程

1. 自注册 N01 → 登录无班级空状态；教师导入同学号同姓名 → 密码不变 → 学生获得正确作业可见性。同时保留 X01、未提交学生和非指定学生的隔离证据。
2. 教师经页面创建编程草稿，学生不可见；配置真实公开/隐藏用例、资源限制后发布；学生页面收到与服务端一致的数据。
3. A01 经浏览器真实提交 AC，再提交 WA/CE/RE/TLE 等样本，累计至少 6 版；取 worker/容器关联证据。每种结局至少一次浏览器提交与真实结果展示，批量脚本用于额外变体。
4. 浏览器检查旧版、分页、草稿、重载、切账号；截止作业仍可读历史但直接提交 API 拒绝。教师查看当前版本并与作者核对。

### 8.2 C05—C07：真实材料至双向评分

1. 教师经页面创建 FINAL-MAIN，设置双向五人 Panel、Rubric 与足够的未来截止，学生可见；先演示缺视频 INVALID，再上传完整材料形成新 VALID 版本。至少一名学生经页面完成纠错与 6 版历史，其余批量通过真实 API 上传。
2. 两班各 3 份作品均完成真实视频处理、匿名包生成；A06/B06 提供不合格材料，A07/B07 无提交。主线只统计当前有效且匿名材料可用的作品。
3. 等自然提交截止后，教师经页面初始化；核对两组各 15 任务、总计 30、每名评审 3 任务、每份作品 5 人。再次初始化不增加任务；无效/旧版/未完成检查作品被排除。
4. 每个方向至少一名评审经浏览器下载、检查匿名包并完成一份评分；其余任务由真实账号 API 完成。所有正式评分前均先真实下载；记录服务端时间，正常样本等待窗口满足第 6.5 节。
5. 故意保留一份作品的第五条评分暂不提交，验证正式聚合被阻止；再补齐。该失败不得留下部分正式聚合。全部 30 份正式评分用真实接口产生，不直接写评分表。
6. 同时核验他人任务、原始材料、教师分等拒绝访问与响应字段。重复评分/并发分支在专用对象验证，避免破坏主线正常评分分布。

### 8.3 C08：教师评分、风险处理、发布与反馈

1. 教师主动录入并锁定所有作品初评；查看真实材料、五位原始分、评语与算法证据。初评不要求强制盲评，但算法不得改写教师记录。
2. 聚合两个 Panel，核对输入摘要、参数、版本、运行归属、画像、逐项结果与风险；失败停止推进并交接，不伪造成功运行。
3. 验证真实 LOW/MEDIUM 未处理、HIGH 缺复核时发布阻断。T2 尝试复核 T1 初评的 HIGH 被拒；T1 在最新初评锁定后录入复核最终分和理由。
4. 另用专用作业验证“新更正未锁定不能退回旧分发布”。不要为覆盖此分支对已发布主线作业做非法修改。
5. 就绪检查与正式发布前重验一致；教师经页面发布。核对全部最终成绩逐行手算、来源、版本/权重/运行/复核快照；重复发布不新增结果。
6. 作者在发布前后分别经浏览器查分，切换另一有成绩作者验证本人隔离。教师统计、CSV 与数据库结果对账；学生响应不含内部评分与身份。
7. FINAL-SMALL 和 FINAL-NON100 以同样真实上传/双向评审/发布路径补足小样本与非 100 分量表，至少取精确锚点的实际结果，不用 AUTO 夹具冒充现场业务数据。

## 9. 共用专项与浏览器检查

- 页面集：登录、注册、未入班空工作台、学生首页、编程提交、期末上传/历史、评审任务、成绩；教师总览、名单/知识点、作业配置/详情、评分/复核/统计。
- 主操作在桌面 1440×900 执行；代表页面复查 768×1024、390×844。登录标题另查 844×390 横屏与手机竖屏；最小宽 320 的标识检查可由既有组件与实际页面补足。记录实际设备缩放与视口。
- 检查关键按钮/输入/下载不被遮挡，无非预期横向溢出；键盘可到达主要操作、焦点可见；不声明全设备/完整无障碍认证。
- 归并演算核对真实排序轨迹、暂停/单步/重播、页面隐藏/离屏、减少动态效果；它不作为学生代码判题证据。
- 会话与异步：切账号/作业、退出/过期、快速路由切换、旧请求晚到、历史详情失败、存储受限和重复操作。可用组件受控响应验证难以稳定重现的时序，真实浏览器再核验主路径。
- 权限表按“教师/作者/同班非作者/指定评审/其他评审/外班/未入班/未登录”逐类对相关对象检查，不要求给每个身份强行调用所有无关端点。成功与拒绝均核对内容和副作用。
- 系统错误仅在 FAULT 注入：队列不可达、worker 中断/恢复、Docker 连接失败、坏视频/ffmpeg 处理失败、落库异常。依据实际重试规则观察终态并记录恢复过程，不能要求断开 worker 就立即 SYSTEM_ERROR。
- 数据库约束：AUTO 内以应用正常连接或拟用于算法访问的实际角色测试 UPDATE/DELETE/归属篡改拒绝，事务回滚后检查历史不变。未配置独立算法角色时如实记录，不用超级用户或 PUBLIC 的 REVOKE 结果声称已证明完整最小权限。

## 10. 缺陷、修复与复验

| 级别 | 判定示例 | 处理 |
| --- | --- | --- |
| S0 严重 | 越权/身份泄露、错误成绩公开、历史损坏、跨库误操作 | 停止相关链路，保留证据并立即交接；必须关闭 |
| S1 主要 | 核心流程不能完成、真实判题/视频不可用、五人或发布约束失效、必要操作被 UI 阻断 | 必须修复复验后才能通过 |
| S2 一般功能 | 非主路分支错误、错误提示致使无法正确处理、分页/恢复不符合契约 | 属于必查功能缺陷，仍须修复；不能因级别低而自动接受 |
| S3 轻微外观 | 不影响操作、理解、权限及数据的间距/对齐等问题 | 可由用户逐项明确接受并留理由；否则保持未关闭 |

状态：NEW → 已复现/待补证据 → 已分派 → 修复提交就绪 → 待复验 → CLOSED；复验失败为 REOPENED。环境 BLOCKED 单列，不能把其伪装成已关闭的功能缺陷。

复验至少执行原失败用例及其具体变体、相关权限/历史边界，并按影响增加测试：

| 修复影响 | 必须增加的复验 |
| --- | --- |
| 认证/公共权限 | C01、两角色登录、评审资格、材料下载和学生查分隔离 |
| 材料/匿名化 | C05/C06/C07；真实 V、旧版检查不复活、失败上传保留原版 |
| 判题/队列 | C03/C04；真实 J、基础设施错误、本人结果恢复 |
| 画像/风险/聚合 | C07/C08；小样本精确锚点、异常处理、版本复用、发布公式 |
