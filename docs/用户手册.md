# 用户手册

## 登录与账号

通过课程提供的网址打开登录页，输入账号和密码。教师账号由课程管理员提供；学生账号由教师在“班级与学生”中添加或批量导入，登录账号通常为学号。

首次登录后，点击右上角“修改密码”，输入当前密码并两次填写新密码。新密码长度为 10～128 位。修改后当前设备获得新会话，其他旧会话失效。离开公共电脑前退出登录。

## 教师工作流程

### 1. 准备班级与知识点

在“班级与学生”中建立课程班级，添加或导入学生，核对学号、姓名和所属班级。批量导入新账号时需要初始密码；导入已有账号时密码可留空，保留其原密码。

在知识点管理中查看所属大章、知识点名称与内容说明。期末微课选题覆盖算法分析、图搜索、贪心、分治、动态规划、网络流、数据结构、字符串、图优化、复杂性及高级算法专题。学生通过大章筛选后认领具体知识点。

### 2. 新建并发布作业

| 类型 | 教师需要准备 |
| --- | --- |
| 编程题 | 题目、输入输出说明、公开与隐藏用例、资源限制 |
| 算法分析、证明、开放问答 | 题面、关联知识点、参与班级与提交截止时间 |
| 期末微课 | 两个参与班级、提交与评审截止时间、逐项评分标准、成绩组成 |

先保存草稿，检查题目、班级与截止时间，再确认发布。期末微课的评审截止时间应晚于提交截止时间。评分表与成绩比例在发布前确定，发布后保持固定。

期末微课的教师分与同伴分默认占 60% / 40%，可在草稿中修改，合计须为 100%，支持两位小数的百分比。例如教师 90 分、同伴聚合 80 分，按 70% / 30% 合成得到 87 分。

### 3. 查看提交

编程题可查看学生历次提交、代码、判题结果及编译反馈。在线作答题可查看完成情况、当前答案和历史版本，这三类文本题在提交后完成。

期末微课可查看选题、当前材料、检查状态和历史版本。有效作品通过材料检查后进入评审分配。尚未分配评审的作品，在提交开放期间可更新；作品被分配后锁定当前版本，让教师与学生评委评阅同一份材料。

### 4. 启动跨班评审

1. 打开分配预览，查看两个班的有效作品、评委名单和预计任务量。
2. 核对人数与工作量，确认当前快照，再生成任务。
3. 学生在自己的评审任务页领取系统分配的匿名作品。

教师可在提交截止前启动评审，学生提交与评阅可以并行。后续有新增有效作品时，刷新预览、重新确认并追加分配，已发出的任务和已提交评分保持原记录。

分配以符合条件的有效提交者为基础。两班人数不同，两个班的人均任务量也可能不同。例如 100 人与 40 人各交一份有效作品时，大班每人约评 2 份，小班每人约评 12～13 份。预览页显示本次实际负担。

每份作品需要对方班五名不同学生。系统还检查本轮两人直接互评等约束，具体人数条件见[算法设计](算法设计.md#人数条件与分配失败)。生成失败时，按页面诊断调整名单或补齐有效提交，再重新预览确认。

### 5. 处理缺评

查看未完成任务与补评队列。需要更换评委时，由教师对未完成任务发起替补，系统从对方班选择符合条件、尚未评过该作品的学生，并考虑其当前任务量。

替补操作保留原任务、新任务及操作记录。已经完成的评分保留。每份作品最终仍需五份完整有效评分；即使同伴成绩权重设为 0%，完整评审流程仍需完成。

### 6. 结束提交并完成评分

在确认材料接收结束后，使用“结束提交”。这项操作停止新作品和新版本上传，已开始的评审继续进行。自然提交截止也会停止接收。

补齐最终新增作品的分配和评分，再触发正式聚合。教师按评分表完成初评并锁定。初评、同伴原始评分与聚合结果分别保存；教师评分更正以新版本记录，原版本仍可追溯。

### 7. 处理异常与最终复核

| 页面状态 | 教师操作 |
| --- | --- |
| 普通作品 | 核对已锁定初评分、同伴聚合结果与成绩预览 |
| LOW / MEDIUM 待处理提示 | 阅读证据，明确确认或驳回 |
| HIGH 高风险作品 | 进入评分工作台完成最终复核 |

HIGH 作品的复核页面展示作品材料、第一次教师分、五名学生的原始分、聚合分和异常证据。由最初评分的同一位教师填写一个复核最终分并锁定，无需重填整张评分表。复核理由、初评反馈、教师改分原因以及一般异常处理说明均为选填，操作人、时间和评分版本照常记录。

高风险作品最终成绩直接采用该复核分；其他作品按作业设置的比例合成。评分异常说明某次评分需要核查，教师根据材料与证据作出判断。

### 8. 发布成绩并反馈

打开发布前检查，逐项完成页面列出的事项：结束提交、最终作品分配、每份五评、成功聚合、教师锁分、异常处理与高风险复核。检查通过后发布。

发布后，学生可查看本人成绩与汇总反馈。教师可查看统计并导出成绩来源，包括教师分、同伴聚合分、作业权重、最终分和复核来源。正式成绩与来源快照保存，便于后续核对。

### 9. 关闭、恢复与删除

关闭作业会暂停学生提交与评审；恢复后按原阶段和原截止时间继续。需要继续接收材料时，恢复操作本身不会延长已经到达的截止时间。

删除作业后，师生正常列表和旧链接均无法再访问。系统保留底层业务与审计记录，已发布成绩的历史内容保持原值。

## 学生工作流程

### 编程题

从作业列表进入题目，阅读输入输出、公开样例与资源限制，在编辑器中编写 C++17 代码并提交。结果包括通过（AC）、答案错误（WA）、超时（TLE）、运行错误（RE）和编译错误（CE）。排队、运行中与系统故障会单独展示。

查看提交历史时注意版本：当前编辑器中的草稿可能与某次已判题代码不同。“问助教”可以结合所选判题版本解释错误，也可以解释当前代码或选中片段，见[AI 辅助特色](AI辅助特色.md)。

### 在线作答题

算法分析、证明和开放问答在题目页填写文本答案，提交即完成。开放期间可以追加新版本，历史答案保留。页面接收纯文本，可填写公式记号和伪代码。

### 期末微课

1. 进入期末作业，选择所属大章和知识点，阅读说明后认领。
2. 准备 PPTX、MP4 讲解视频、源码、至少三组输入输出测试、README 和至少三个例题。
3. 打包为 ZIP，外层文件名采用 `学号_姓名_知识点编号.zip`，知识点编号以页面实际显示为准。
4. 选择 ZIP，系统自动识别材料路径及同名 `.in` / `.out` 测试；核对材料清单，补充例题所在 PPT 页码，或使用包内清单。
5. 点击“上传并检查”，查看材料检查结果；有缺失或格式问题时按提示修正。
6. 检查中可刷新提交状态；检查通过后保留当前版本与提交历史，等待任务分配。

ZIP 最大 500 MiB。材料路径填写包内相对路径，例如 `slides/lesson.pptx`、`video/lesson.mp4`，使用 `/` 分隔。使用 PPT 页码声明例题时填写至少三个页码；也可在材料清单中声明例题文件。具体可上传样例见[材料样例](../samples/README.md)。

被分配评审前，可在提交开放时更新作品；分配后当前版本锁定。上传材料时去掉正文、画面、配音与源码注释中的学号姓名等个人线索，以便开展匿名评审。

### 成绩与反馈

教师发布期末成绩后，在对应作业中查看本人结果及汇总反馈。评委的匿名身份不会在学生反馈中公开。教师尚未发布时，页面显示当前进度。

## 学生评委工作流程

学生仍使用自己的课程账号。在“评审任务”中完成系统分配的跨班匿名作品，无需另注册评委账号。

1. 在“待完成”列表中选择任务，查看截止时间和评分表。
2. 下载匿名材料，阅读 PPT、观看视频、查看代码与例题。打开材料会记录评审开始时间。
3. 对评分表全部项目填写分数，分数须在对应满分内，并填写有依据、可改进的评语。
4. 提交后在“已提交”列表核对评分。
5. 评审仍开放且未进入后续评分阶段时，可点击“修改评分”，填写修改原因后提交新版本。系统保留修改记录供教师查看。

评阅时依据作品内容和评分标准作答。任务列表仅开放本人被分配的材料，其他评委分数和教师初评分在此阶段独立保留。

评审截止、作业关闭或进入后续评分阶段后，按页面状态查看只读记录。教师替补某项任务后，原评委不再访问该停用任务。

## 常见情况

| 看到的情况 | 如何处理 |
| --- | --- |
| 无法登录 | 核对教师提供的账号、密码；连续失败触发限速时稍后再试 |
| 提示设备时间异常 | 校准系统时间后重新操作 |
| 上传后一直检查中 | 点击“刷新提交状态”；持续异常时向教师提供作业和提交编号 |
| 作品不能更新 | 查看截止时间、作业开放状态及当前版本是否已分配评审 |
| 没有评审任务 | 教师需要先确认名单并生成分配，新增作品也需要教师追加任务 |
| 无法修改已提交评分 | 查看评审截止和作业阶段，修改窗口以页面状态为准 |
| AI 暂不可用 | 查看配额与课程配置状态，由教师核对连接和服务额度 |
| 暂无期末成绩 | 等待教师完成评分、复核与发布 |
