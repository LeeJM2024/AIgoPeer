# 给组员 2：学生端、评审端与自动测评开发说明

你在 `feature/member2-student-*` 分支开发。先从 `develop` 拉新分支，完成一个小功能就提交并发起合并请求；不要直接向 `main` 或 `develop` 推送。

## 你可以直接使用的公共部分

* 前端已在 `frontend/`，入口是 `src/main.js`，路由是 `src/router/index.js`，统一请求函数是 `src/api/client.js`；
* 评审任务页面及 API 文件已建好：`src/views/ReviewerTasksView.vue`、`src/api/reviewer.js`；
* 后端评审路由在 `backend/app/api/routes/reviewer_tasks.py`，数据表已由初始迁移创建；
* 接口字段以顶层 `04-接口文档.md` 为准。改字段之前先和负责人确认。

## 建议按这个顺序做

1. 做登录后学生首页：作业列表、本人提交状态、入口按钮。
2. 做期末作业包上传：调用 `POST /api/assignments/{id}/project-submissions`，展示材料检查中的状态；轮询 `GET /api/submissions/{id}/material-check`，把缺的 PPT、视频、例题、代码、测试、README 明确提示出来。
3. 做代码提交与结果页：提交后轮询 `GET /api/code-submissions/{id}`，清楚区分 AC、WA、TLE、RE、CE。
4. 完成评审任务列表、匿名材料浏览、Rubric 打分表和评语提交。
5. 做成绩反馈页。成绩没发布时只显示“暂未发布”；发布后只展示当前学生自己的结果。

## 评审端绝不能越过的边界

后端给评审人的响应只能有 `anonymous_token`、材料、Rubric 和任务状态。不能展示或缓存 `author_id`、姓名、学号、教师分、聚合分、异常提示、其他评审人的内容。页面也不能根据班级 ID 猜作者。

提交评分时，分数不得超过后端返回的 `max_score`，必须带评语和开始时间。接口会由你补齐，但必须先检查任务属于当前登录用户，且目标班与评审人班不同；不要只依赖前端隐藏按钮。

## 你要修改的范围

* 前端：`frontend/src/views/`、`frontend/src/components/`、`frontend/src/api/`；
* 后端学生/评审路由：`backend/app/api/routes/`；
* 与提交、材料检查、判题相关的 service；
* 必要的数据库字段只能通过新的 Alembic 迁移添加。

不要修改 `algorithm/` 的算法逻辑，也不要写教师评分、最终成绩发布接口。若需要接口字段变化，在合并请求中同时更新 `04-接口文档.md` 和测试。

## 合并前自检

* 普通学生访问 `/api/reviewer/review-tasks/mine` 返回 403；
* 评审人只看得到自己的对方班任务，接口响应不含作者身份；
* 缺视频或 README 的包显示 `INVALID`，不会生成评审入口；
* 发布成绩前，学生不能获取教师分、聚合分、评语；
* 附上至少一个常规测试和一个权限/边界测试。
