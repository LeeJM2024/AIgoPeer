# 组员 2：学生端交付与接入说明

更新日期：2026-10-15。代码基线：`6499772`（PR #8 合并提交）。本文将原开发待办更新为已交付能力及维护边界；后续新增需求需另行确认。

## 1. 当前交付状态

学生端已形成三条闭环：日常编程作业提交与判题、期末材料上传与版本追溯、跨班匿名互评与本人查分。学生侧相关功能已通过 PR [#6](https://github.com/LeeJM2024/AIgoPeer/pull/6)、[#7](https://github.com/LeeJM2024/AIgoPeer/pull/7)、[#8](https://github.com/LeeJM2024/AIgoPeer/pull/8) 合入 `develop`，`student` 已同步至上述基线。

| 能力 | 已交付行为 | 关键边界 |
| --- | --- | --- |
| 我的作业 | 按当前学生在籍班级列出非草稿作业、本人提交摘要及操作入口 | 不返回其他学生记录；截止后仍可查看 |
| C++17 提交与判题 | 公开题面/样例、提交、排队/运行状态、AC/WA/TLE/RE/CE、基础设施异常提示 | 不返回隐藏用例或旧源码；`SYSTEM_ERROR` 不等同学生代码错误 |
| 编程提交恢复与历史 | 从服务端恢复最近提交；下方每页 5 条本人历史，旧版判题详情只读 | 查看历史不替换编辑器代码或当前判题；草稿按账号和作业隔离，仅在本浏览器保存 |
| 期末上传 | 知识点认领、ZIP 与材料清单提交、缺失项和提示项展示 | 上传前与收包完成入库时检查服务端截止时间及阶段；跨截止拒绝并保留原当前版本 |
| 当前期末提交恢复 | 重载恢复当前版本和材料检查；短时轮询后支持“刷新提交状态” | 刷新读取服务端状态，不重新执行材料检查 |
| 期末历史 | 上传页下方每页 5 条、最新在前、当前版本标记、各版材料检查详情 | 旧版 `PENDING` 只手动刷新；无下载、删除、回滚或重新检查入口 |
| 指定匿名评审 | 有有效任务才显示入口；下载匿名材料后逐项评分并提交评语 | 对方班指定五人；只读本人任务；一次提交后不可修改 |
| 本人成绩 | 发布后显示最终总分、匿名评语、教师反馈和 Rubric 说明 | 发布前拒绝；不显示教师原始分、聚合分、维度具体得分、风险或评审人身份 |

`VALID` 表示自动材料完整性检查通过，不代表内容正确或质量合格。原 ZIP 文件名可包含提交人的学号与姓名，但给评审人的派生材料包不得包含这些身份信息。

## 2. 页面、接口与代码入口

以下路径均相对于仓库根目录；API 完整字段、错误码及分页参数以 [接口文档](../04-接口文档.md) 为准。

| 页面 | 浏览器路由 | 前端入口 |
| --- | --- | --- |
| 我的作业 | `/student` | `frontend/src/views/student/StudentWorkspaceView.vue`、`frontend/src/components/student/StudentAssignmentList.vue` |
| 编程提交 | `/student/assignments/:assignmentId/programming-submission` | `frontend/src/views/student/StudentProgrammingSubmissionView.vue`、`frontend/src/components/student/ProgrammingSubmissionHistory.vue` |
| 期末提交 | `/student/assignments/:assignmentId/project-submission` | `frontend/src/views/student/StudentProjectSubmissionView.vue`、`frontend/src/components/student/ProjectSubmissionHistory.vue` |
| 我的评审 | `/reviewer/tasks` | `frontend/src/views/ReviewerTasksView.vue` |
| 本人成绩 | `/student/assignments/:assignmentId/grade` | `frontend/src/views/student/StudentGradeView.vue` |

| 接口 | 用途 |
| --- | --- |
| `GET /api/student/assignments` | 本人作业列表与提交摘要 |
| `GET /api/student/assignments/{id}/programming-problem` | 题面与公开样例 |
| `POST /api/assignments/{id}/code-submissions` | 提交 C++17 源码 |
| `GET /api/code-submissions/{id}` | 本人指定版本判题汇总 |
| `GET /api/student/assignments/{id}/code-submissions` | 本人编程分页历史 |
| `GET /api/student/assignments/{id}/topics` | 知识点与本人认领 |
| `POST /api/assignments/{id}/topic-claim` | 认领知识点 |
| `POST /api/assignments/{id}/project-submissions` | 上传 ZIP 和 manifest |
| `GET /api/student/assignments/{id}/project-submission` | 当前期末提交及是否可上传 |
| `GET /api/student/assignments/{id}/project-submissions` | 本人期末分页历史 |
| `GET /api/submissions/{id}/material-check` | 本人指定版本材料检查（教师另有权限） |
| `GET /api/reviewer/eligibility` | 当前学生是否有有效评审任务 |
| `GET /api/reviewer/review-tasks/mine` | 本人有效任务，默认待开始及进行中 |
| `GET /api/reviewer/review-tasks/{id}/materials/archive` | 匿名材料，首次成功下载由服务端记录开始时间 |
| `POST /api/reviewer/review-tasks/{id}/reviews` | 完整 Rubric 分数和非空评语 |
| `GET /api/student/grades?assignment_id={id}` | 本人已发布结果 |

前端 API 位于 `frontend/src/api/student/`、`frontend/src/api/reviewer.js`；公共请求和认证在 `frontend/src/api/client.js`、`frontend/src/api/auth.js`。

后端入口：

- 学生作业、成绩、知识点、期末和编程路由：`backend/app/api/routes/student/`；对应服务在 `backend/app/services/student/`。
- 材料检查和匿名化：`backend/app/services/student/material_check_service.py`、`backend/app/services/student/review_anonymization_service.py`；后台任务执行检查和派生包生成。
- 判题：`backend/app/services/judge_runner.py`、`backend/app/workers/judge_worker.py`；Redis 队列由独立 worker 消费，C++17 在 Docker 中执行。
- 评审路由：`backend/app/api/routes/reviewer_tasks.py`；任务初始化集成入口为 `backend/app/services/review_task_service.py`，算法规则仍由成员 3 维护。

## 4. 启动与演示

新环境、已有环境的分别启动方法、材料准备和三条逐步演示路径见 [学生端交付验收与演示清单](学生端交付验收与演示清单-20261015.md)。

必要依赖：PostgreSQL、Redis、后端、前端；实际编程判题还需要判题镜像、运行中的 `judge-worker` 及 Docker；期末匿名视频处理需要后端镜像中的 `ffmpeg`。仅启动 Web API 不足以证明实际判题正常。

本机 `local-reports/` 中的 QA 身份、截图、合成材料、报告和恢复备份不随仓库交付。需要现场复验时由数据保管人提供合成材料，不复制真实学生资料或本机凭据到仓库。
