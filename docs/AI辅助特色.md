# AI 辅助特色

AlgoPeer 把 AI 放在课程学习和教学评阅的具体场景中：学生围绕正在写的代码和知识点提问，教师根据真实学习统计安排教学，并通过视频中的时间点证据辅助评阅微课。

## 四项课程能力

| 特色 | 入口 | 可以怎样使用 |
| --- | --- | --- |
| 结合版本的编程助教 | 学生编程题页“问助教” | 理解题目、解释代码、分析某次判题错误、讨论复杂度和改进方向 |
| 围绕知识点连续学习 | 学生“知识点学习” | 按大章或关键词寻找知识点，讲概念、看例子、问证明、比较方法与练习 |
| 根据课堂证据提出教学建议 | 教师“学习分析”中的 AI 教学建议 | 根据当前班级的通过情况与错误分布安排复习、讲解和练习 |
| 带时间点证据的视频评阅 | 教师评分页“分析视频” | 查看整段讲解的内容概述、逐项建议与视频证据，点击时间点回看 |

## 编程助教：问题与代码版本对应

编程助教可以结合当前题目、公开样例、编辑器代码、选中片段，以及本人选定的判题版本回答问题。

例如某次提交得到 TLE，学生可以选择那次判题记录，询问“这份实现的瓶颈在哪里”。继续修改编辑器后，也可询问“这次修改是否降低了复杂度”。系统会标明当前草稿是否与已判题版本不同，让讨论对象保持清楚。

选中代码片段后，可以专门解释递归边界、状态转移或某个循环。提问示例：

- “先解释题目的约束怎样影响时间复杂度，再给我一个思路提示。”
- “解释我选中的状态转移，指出它依赖哪些已经计算的状态。”
- “结合我选中的判题记录，分析可能遗漏的边界情况。”

教师可以设置辅导方式。默认采用提示式辅导；允许完整题解后，助教提示策略可以进一步给出完整实现。编程助教围绕公开题面与本人代码工作，隐藏用例保持在判题环境中。

## 知识点学习：沿着课程目录追问

学生打开“知识点学习”，按大章节或关键词找到知识点，再围绕当前主题连续提问。适合把概念、例子、正确性与复杂度连起来理解。

例如在归并排序中先问“合并两个有序区间时维护什么不变式”，再问“相等元素怎样处理才稳定”，最后请助教给出一组练习。换到新知识点后，使用对应的独立对话上下文。

回答支持标题、列表、表格、数学公式及可复制代码块，便于阅读算法推导和代码说明。

## 教学建议：围绕当前班级的数据

教师在学习分析中选择全部班级或某个班级，再打开 AI 教学建议。系统将该范围的真实课程统计作为上下文，包括提交、通过情况、错误分布和知识点观察结果。

可以询问“下一节课优先复习哪些内容”“针对当前常见错误设计三道练习”或“怎样安排二十分钟的复杂度分析复习”。切换班级范围时，对话按范围区分，便于对照不同班的学习进度。

统计指标的计算方式见[学习分析](学习分析.md)。

## 视频辅助评阅：建议可以回到原视频核对

教师在作品材料区点击“分析视频”，系统使用该作品提交清单中的视频与本作业评分表开展分析。

视频最长 30 分钟，系统按每 120 秒切片覆盖完整时长，处理画面并保留声音，再汇总逐项结果。教师可以看到：

- 内容概述，快速了解讲解结构与覆盖内容。
- 与本次评分表对应的逐项建议分和理由。
- 模型自评置信度，辅助判断建议需要进一步核对的位置。
- 视频时间点证据，点击后打开原视频并定位。

分析期间可以离开页面，返回后继续查看进度；支持停止、重试以及查看最近十次记录。相同输入的已完成分析可以复用，明确重新分析会创建新记录。

每位教师最多同时分析两个视频。停止操作在当前模型调用结束后阻止后续结果保存，服务商已接收的请求可能已经产生用量。模型自评置信度来自本次分析结果，教师仍结合原材料和评分标准填写正式评分。

AI 结果单独保存。教师初评、学生评审、异常复核和最终成绩仍通过各自的评分流程完成。

## 教师首次配置

### 文字助教

1. 打开“AI 辅助”，选择“文字助教”。
2. 填写模型服务的 HTTPS Base URL、模型名称和自己的 API Key。服务应兼容 Chat Completions 协议。
3. 点击“测试文字连接”，确认当前账号和模型可用。
4. 设置学生每日提问次数与是否允许完整题解，再点击“保存配置”。

测试连接与保存配置是两步操作。页面的预填地址和模型名可按服务商账号实际支持的内容调整。

文字配置对课程学生统一生效。学生默认每日 30 次，教师可以设为 1～200 次；教师每日上限为 200 次。按北京时间自然日计数，已经发送给模型但调用失败的请求也会计入额度。

### 视频辅助评阅

1. 在“AI 辅助”中切换到“视频辅助评阅”。
2. 选择 Qwen-Omni 或 Gemini，填写对应模型名、HTTPS 接口地址和 API Key。
3. 点击“测试视频连接”。系统生成两秒带声音的测试视频，进行实际音视频调用。
4. 测试通过后保存，再到作品评分页启动分析。

视频模型需要同时理解画面与声音。Qwen 使用 Chat Completions 音视频协议，Gemini 使用原生 `generateContent` 协议；自定义地址应匹配所选服务商协议。视频与文字模型分别配置。

连接测试会调用外部模型并产生相应用量，视频连接测试使用系统生成的测试片段。实际使用费用由所配置的模型服务账号承担。

### 更换或移除配置

保存后，密钥输入框自动清空。以后保存时留空可继续使用已有密钥；更换接口地址时需要重新填写密钥，视频服务商变化时也需重新填写。

删除视频配置会停止该教师当前分析任务，保留历史结果。文字助教配置由课程统一管理，视频配置按教师保存。

## 连续对话与恢复

对话按用户、功能模式和题目、知识点或班级范围区分。重新进入页面可恢复该上下文最近的对话，最多显示最近 30 轮，模型使用最近六个成功问答和当前上下文继续回答。

每位用户同时处理一个文字问题。刷新页面后可以恢复进行中的请求；超过十分钟仍未完成的记录标记为中断，可重新提问。视频分析也保存进度与历史；服务进程中断时按页面提示停止或重试。

## 使用时怎样判断下一步

| 页面情况 | 下一步 |
| --- | --- |
| 文字或视频连接测试失败 | 核对地址、协议、模型权限、密钥和服务额度 |
| 学生看不到可用 AI | 教师保存有效的课程文字配置，学生确认已加入课程班级 |
| 今日次数已用完 | 次日继续，或由教师调整学生配额 |
| 想讨论某次提交错误 | 选择对应判题版本，再给出具体问题 |
| 视频建议需要核对 | 点击证据时间点，结合原视频确认上下文 |
| 分析显示中断或失败 | 查看提示，调整材料或服务配置后重试 |

关于模型调用上下文、账号权限、密钥保护与备份，见[安全与隐私](安全与隐私.md)和[部署与运维](部署与运维.md)。
