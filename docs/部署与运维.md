# 部署与运维

本指南面向负责安装和维护 AlgoPeer 的课程管理员。教师和学生的日常使用见[用户手册](用户手册.md)。

## 服务组成

| 服务 | 职责 |
| --- | --- |
| 前端静态站点 | 提供登录、课程工作台、提交和评分页面 |
| FastAPI 后端 | 认证、课程业务、材料处理、评分与 AI 调用 |
| PostgreSQL 16 | 保存课程数据、会话、评分版本和运行记录 |
| Redis 7 | 提供判题队列 |
| 判题 worker 与 C++ 镜像 | 消费提交，在隔离容器中编译运行代码 |
| 持久化材料存储 | 保存学生材料、处理结果和 AI 密钥的加密主密钥 |

后端镜像自带 FFmpeg，用于视频和匿名材料处理。前端构建使用 Node.js 20 或更高版本，CI 使用 Node.js 22；本机运行 Python 工具时使用 Python 3.11 或更高版本。

## 本地体验

Windows 使用 Docker Desktop 时先启用 WSL 2 并确认 Docker 引擎运行。在仓库根目录执行：

```powershell
Copy-Item .env.example .env
```

编辑 `.env`，设置数据库账号密码，令 `DATABASE_URL` 与 `POSTGRES_*` 保持一致；Compose 中数据库主机为 `db`。设置独立随机的 `JWT_SECRET` 和 `INTERNAL_API_TOKEN`。本地使用 `APP_ENV=development`，默认前端来源为 `http://localhost:5173`。

```powershell
docker compose up -d --build
docker compose exec backend python scripts/seed_demo.py
```

后端启动时自动执行 `alembic upgrade head`。初始化脚本为本地体验建立两个班、演示账号与题目；真实作品和评审由操作者按页面流程完成。

在另一个终端启动前端：

```powershell
cd frontend
npm ci
npm run dev
```

打开 `http://localhost:5173/login`。教师账号 `T001`，学生 `D101`～`D110`、`D201`～`D210`，初始密码 `AlgoPeer2026!`。默认密码只用于本地演示。生产模式会拒绝执行演示初始化脚本。

本地后端健康检查为 `http://127.0.0.1:8000/api/health`，OpenAPI 为 `http://127.0.0.1:8000/docs`。前端通过 `/api` 代理访问后端。使用 `127.0.0.1` 打开前端时，在 `CORS_ORIGINS` 中也配置完整的对应来源。

## 正式环境配置

使用 `docker-compose.production.yml` 部署数据库、Redis 和后端。该配置使用独立数据卷、只读后端容器和资源限制，将后端绑定在主机 `127.0.0.1:8000`，数据库与 Redis 保持在内部网络。

正式服务还需要 HTTPS 网关、构建后的前端，以及独立部署的判题 worker。按以下顺序准备。

### 1. 配置域名、密钥与数据库

| 配置 | 设置方式 |
| --- | --- |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | 使用独立生产库与私有密码 |
| `DATABASE_URL` | `postgresql+psycopg://账号:URL编码后的密码@db:5432/库名` |
| `JWT_SECRET` | 至少 32 字符的独立随机值 |
| `INTERNAL_API_TOKEN` | 另一个至少 32 字符的随机值，与 JWT 密钥不同 |
| `CORS_ORIGINS` | 实际 HTTPS 前端来源，例如 `https://course.example.edu`，结尾无 `/` |
| `TRUSTED_PROXY_IPS` | 仅填写实际反向代理来源 IP，按部署网络确定 |

生产 Compose 已设置 `APP_ENV=production` 与容器内材料目录 `/app/storage`。配置真实密码时同时核对数据库 URL 中的转义。配置文件与真实密钥由部署管理员保管。

```powershell
docker compose -f docker-compose.production.yml up -d --build
docker compose -f docker-compose.production.yml ps
docker compose -f docker-compose.production.yml logs --tail 100 backend
```

生产模式关闭交互式 API 文档，健康检查仍为 `/api/health`。

### 2. 部署前端与 HTTPS 网关

在 `frontend` 目录运行：

```powershell
npm ci
npm run build
```

将 `frontend/dist` 作为静态站点目录。推荐使用同源 `/api`，将该路径转发给后端；其余前端路由使用 `index.html` 回退，让刷新课程页面时仍能打开对应视图。

以下为同机 Nginx 配置示例，替换域名、证书与静态目录后使用：

```nginx
server {
    listen 443 ssl;
    server_name course.example.edu;
    ssl_certificate /etc/ssl/course/fullchain.pem;
    ssl_certificate_key /etc/ssl/course/privkey.pem;

    root /srv/algopeer/frontend/dist;
    index index.html;
    client_max_body_size 501m;

    add_header X-Frame-Options DENY always;
    add_header X-Content-Type-Options nosniff always;
    add_header Referrer-Policy no-referrer always;
    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header Content-Security-Policy "frame-ancestors 'none'" always;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 180s;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

为 HTTP 配置到 HTTPS 的跳转，并按课程并发规模配置网关的连接与请求频率限制。构建后的 HTML 已包含脚本、样式、媒体等来源策略；网关补充页面嵌入策略。

若前端使用独立 API 域名，在构建前配置 `VITE_API_BASE` 为该 HTTPS 服务地址，并使后端允许实际前端来源。正式服务使用静态构建产物。

### 3. 部署判题 worker

生产 Compose 提供核心后端服务。开展自动判题时，在独立判题节点部署以下镜像与进程：

```powershell
docker build -f backend/judge/Dockerfile -t algopeer-judge-cpp:latest .
docker build -f backend/judge-worker.Dockerfile -t algopeer-judge-worker:latest .
```

worker 镜像的默认入口为 `python -m app.workers.judge_worker`。部署配置可参考 `docker-compose.yml` 中的 `judge-worker`，按实际网络准备：

- 指向课程服务的私网 `DATABASE_URL` 和 `REDIS_URL`。
- 同一 `JUDGE_QUEUE_NAME`，默认 `algopeer:judge:queue`。
- `JUDGE_IMAGE=algopeer-judge-cpp:latest`，以及与 Docker 数据卷一致的 `JUDGE_WORK_VOLUME`。
- 将专用工作卷挂载到 `/judge-work`；worker 需要调用该节点 Docker，沙箱容器通过同名卷访问工作文件。
- 配置并发、源码大小、总运行时限、输出与编译输出上限。

应用、数据库及模型密钥保留在核心服务节点，通过受控私网向判题节点提供必要连接。正式课程开放前，提交一份可通过程序和一份错误程序，确认排队、执行、结果反馈与历史查询均正常。

### 4. 建立正式教师账号

正式数据库的首个教师由课程管理员创建。打开后端容器中的交互式 Python：

```powershell
docker compose -f docker-compose.production.yml exec backend python
```

执行下面的代码。密码通过终端隐藏输入，由应用提供的函数生成哈希；账号已存在时数据库会拒绝重复创建。

```python
import re
from getpass import getpass
from sqlalchemy import text
from app.core.security import hash_password
from app.db.session import SessionLocal

def create_teacher():
    account = input("Teacher account: ").strip()
    name = input("Display name: ").strip()
    password = getpass("Initial password (10-128 characters): ")
    if not re.fullmatch(r"[A-Za-z0-9_.@-]{1,64}", account):
        raise ValueError("Use 1-64 ASCII letters, digits, or _.@-")
    if not 1 <= len(name) <= 100 or any(ord(c) < 32 for c in name):
        raise ValueError("Use a display name of 1-100 characters")
    if not 10 <= len(password) <= 128:
        raise ValueError("Password must contain 10-128 characters")
    with SessionLocal.begin() as db:
        db.execute(text("""INSERT INTO users
            (student_no, name, password_hash, system_role)
            VALUES (:account, :name, :password_hash, 'TEACHER')"""),
            {"account": account, "name": name,
             "password_hash": hash_password(password)})
    print("Teacher account created")

create_teacher()
```

首次教师登录后修改初始密码，再在页面中建立班级并导入学生。当前课程按单教师使用，保持统一教师身份完成初评与高风险最终复核。

### 5. 配置课程 AI

教师在“AI 辅助”页面分别配置文字助教和视频辅助评阅，测试连接后保存。学生共享课程文字配置，使用时无需填写密钥。

配置保存后会在私有材料存储中生成 `.private/video-ai.key`。该文件用于解密数据库中的模型密钥，与数据库配套备份。具体功能见[AI 辅助特色](AI辅助特色.md)。

## 备份与恢复

完整备份包含数据库、材料存储和部署配置。生产存储卷名以 `docker compose -f docker-compose.production.yml config --volumes` 以及实际 Docker 卷名为准。

PostgreSQL 备份示例，先在容器中生成自定义格式文件，再复制到主机：

```powershell
docker compose -f docker-compose.production.yml exec db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/algopeer.dump'
docker compose -f docker-compose.production.yml cp db:/tmp/algopeer.dump ./algopeer.dump
```

材料与密钥备份到受限目录：

```powershell
docker compose -f docker-compose.production.yml cp backend:/app/storage ./storage-backup
```

在维护窗口暂停材料与评分写入，使数据库备份与材料副本属于同一时间点。记录对应代码提交、迁移版本和备份日期，保管好 `.env` 与 `.private/video-ai.key`。

恢复时先在独立环境中使用对应版本代码，恢复数据库、存储与密钥，再核对账号登录、作品读取、评分来源及模型配置解密。确认完整后再切换正式入口。

## 升级

先备份，再构建新版本前端与后端。后端启动时运行 `alembic upgrade head`，可在日志中查看迁移结果。版本确认使用：

```powershell
docker compose -f docker-compose.production.yml exec backend alembic current
docker compose -f docker-compose.production.yml exec backend alembic heads
```

当前代码的迁移头为 `20261029_0019`，后续以实际代码为准。升级含服务端会话管理的版本后，旧令牌需要重新登录。

早期固定评委作业进入跨班模型时涉及业务规则切换：在独立副本核对现有作业与迁移要求，按已备份数据安排迁移。正式运行中的课程数据通过迁移管理，演示初始化脚本只用于本地体验。

## 服务检查与故障定位

| 情况 | 查看位置 |
| --- | --- |
| 后端启动失败 | 后端日志、数据库连接、生产密钥校验、迁移状态 |
| 页面打开但登录失败 | `/api` 代理、HTTPS 域名、允许来源、设备时间 |
| 上传被网关拒绝 | 网关请求大小、连接超时、后端日志和 500 MiB 应用限制 |
| 编程提交一直排队 | Redis 连通性、队列名、worker 日志、判题镜像和工作卷 |
| 材料处理失败 | FFmpeg 可用性、文件结构、私有存储与临时目录容量 |
| AI 配置无法解密 | 原加密主密钥是否随数据库一起恢复 |
| 视频任务中断 | 服务进程和模型调用状态，按页面提示停止或重试 |

维护时保留业务日志中的操作与错误编号，避免记录密码、模型密钥或完整服务商错误正文。保护细节见[安全与隐私](安全与隐私.md)。

## 版本验证

前端在 `frontend` 目录执行 `npm test` 和 `npm run build`。后端在安装开发依赖后执行 `python -m pytest tests/backend -q`，通过 `TEST_DATABASE_URL` 指向独立空 PostgreSQL 测试库；设置 `RUN_BROWSER_TESTS=1` 并安装 Playwright Chromium 可覆盖真实浏览器流程。

CI 使用隔离数据库运行后端与浏览器测试，课程正式库用于实际教学。升级前后可用健康检查与一套独立测试账号核对登录、提交、评阅和发布操作。
