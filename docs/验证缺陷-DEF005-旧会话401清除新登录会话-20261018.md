## 复现与结果

1. 在学生会话中放入失效令牌，重新进入学生工作区。
2. 评审资格请求携带旧令牌，真实服务端返回 401；仅将该响应的交付延迟约两秒，响应正文和状态没有替换。
3. 另一请求的 401 使页面进入登录。立即用不同的真实账号 VERIFY-A02 登录，等待登录接口返回 200。
4. 旧资格请求的 401 晚到后，新的本地令牌被删除，页面再次进入 `/login`。

记录的延迟请求状态为 `[401,401,200]`，最终 `has_token=false`。该问题影响重新认证后的会话稳定性；未发现权限提升或他人成绩泄露。

预期：响应只处理其所属会话；旧请求的失效不能注销已建立的新会话。当前会话自身收到有效的 401 时仍应正常清理并要求重登。

## 定位与复验

[api/client.js](D:/算法大作业/AIgoPeer/frontend/src/api/client.js:14) 在任意非登录请求返回 401 时，直接删除当前本地令牌和用户信息、派发会话失效事件，没有比较请求发出时的令牌与当前令牌。

修复时将 401 的处理与发起请求的会话绑定，并保留当前会话的失效处理。回归应包括旧 A 请求晚到时当前 B 会话保留、B 自身 401 清理、退出时旧请求晚到、无令牌请求及多个并发 401；用真实延迟浏览器复验最终路径、账号和令牌是否仍属于新会话。
