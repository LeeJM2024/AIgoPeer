# 编程题与判题接口对接说明

本文是成员 1、成员 2、成员 3 对编程题模块的接口边界约定。完整学生 API 以顶层 [`04-接口文档.md`](../04-接口文档.md) 为准。

## 已提供的学生侧能力

|接口|用途|数据保密规则|
|---|---|---|
|`GET /api/student/assignments/{id}/programming-problem`|读取题目与公开样例|仅返回当前学生可见作业；绝不返回隐藏用例。|
|`POST /api/assignments/{id}/code-submissions`|提交 C++17 源码|仅本人、未截止的 `PUBLISHED/SUBMITTING` 作业可提交。|
|`GET /api/code-submissions/{id}`|轮询本人结果|只返回汇总结果；禁止返回输入、标准输出、实际输出和逐用例结果。|

状态为 `QUEUED`、`RUNNING`、`AC`、`WA`、`TLE`、`RE`、`CE`、`SYSTEM_ERROR`。`SYSTEM_ERROR` 是判题基础设施故障，不得作为学生代码错误、评分依据或算法特征。

## 成员 1：教师端后续接入契约

2026-10-09更新：该契约现已接入教师页面和 API，见 [接口文档第8节](../04-接口文档.md#8-教师集成补充2026-10-09)。
最低要求一个公开及一个隐藏用例；题目和用例仅在无提交的草稿中可改，发布后有数据库触发器保护。
教师可查看当前提交版本的判题汇总，不经过期末五人互评流程。

成员 2 本轮创建以下数据结构，但**不实现教师端页面或教师公开 API**：

* `programming_problems`：一条 `PROGRAMMING` 类型的 `assignments` 对应一条题目；必填 `statement`、`input_description`、`output_description`、`time_limit_ms`、`memory_limit_mb`。
* `programming_test_cases`：字段为 `problem_assignment_id`、`sort_order`、`input_data`、`expected_output`、`is_public`。输入与输出最大 64 KiB，排序在一道题内唯一。

教师端创建题目时必须在同一事务中：创建 `assignments`（类型 `PROGRAMMING`）、绑定班级、创建 `programming_problems`、写入测试用例。建议至少 2 个公开样例和 3 个隐藏用例。隐藏用例只能由教师端受权接口写入和由 `judge-worker` 读取；不得出现在学生 API、浏览器日志、评审端、算法模块或演示截图中。

更新题目或测试用例应仅在未发布或明确的重判流程中进行；已产生提交后直接修改会破坏成绩可复现性，届时需先共同设计版本化规则。

## 成员 3：算法模块边界

算法模块不读取 `code_submissions.source_code`、`programming_test_cases`、编译输出或 Docker 判题日志，也不写入 `code_submissions`。可在后续由负责人明确授权后读取已发布的汇总成绩，不能把 `SYSTEM_ERROR` 当成异常评分证据。

## 运行环境

`judge-worker` 从 Redis 队列取得提交 ID，并以一次性 Docker 容器运行 C++17。运行容器无网络、非 root、只读根文件系统、限制 CPU/内存/PID、每用例 2 秒、整次提交 10 秒。工作进程拥有 Docker socket；Web 后端与前端都没有此权限。开发环境默认单并发，可使用 `JUDGE_WORKER_CONCURRENCY` 配置后续扩展。

## 联调验收

1. 成员 1 创建/种子一题后，成员 2 可读取公开样例且看不到隐藏用例。
2. C++17 的 AC、WA、TLE、RE、CE 分别产生对应状态；题目未发布或过期提交返回 `INVALID_STATE`。
3. 普通学生查询他人的 `code-submissions/{id}` 返回 `404`；响应体不含源码和任何测试内容。
4. Docker/Redis 故障最多自动重试一次，最终为 `SYSTEM_ERROR`，不伪装成 RE 或 CE。
