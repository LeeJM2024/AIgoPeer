## 1. 安全处理流程

浏览器请求依次经过 HTTP 请求大小与来源检查、可信 Host 检查、身份与会话验证、请求频率与防重放检查，再进入课程权限和业务处理。需要登录的项目 ZIP 上传在身份、请求证明和课程权限检查通过后解析文件。

学生材料进入 ZIP 和嵌套 Office 检查后，按材料类型生成匿名评阅材料。编程提交由后台队列交给判题 worker，在受限 Docker 容器中编译运行。

本次加固覆盖账号、教师和学生会话、写接口、材料上传、浏览器展示、视频处理、判题执行及生产部署配置。

## 2. 账号、姓名与密码

### 2.1 全角、半角及不可见字符处理

新增统一的账号规范化函数，应用于登录账号和教师批量导入学生学号：

1. 使用 Unicode NFKC 规范化，将全角字母、数字等转换为对应兼容形式。
2. 去除账号首尾空白。
3. 账号首位必须是 ASCII 字母或数字；其余只允许 ASCII 字母、数字、下划线、点、`@` 和连字符。
4. 拒绝零宽字符、双向控制字符及其他不在允许集合内的字符。
5. 批量导入在规范化后检查学号重复，避免 `D101` 与 `Ｄ１０１` 被当作不同账号。

账号规范化不改变字母大小写。通用账号函数允许最多 100 个字符，教师导入学号仍受业务模型的 32 字符上限约束。

姓名保留正常中文字符，拒绝 Unicode 控制类字符及 `< > : / \ " | ? *` 等会影响材料文件名安全的字符。

密码、源代码和在线答案保留原文，不执行账号式的 NFKC 转换，确保登录密码和程序语义不被改变。系统继续使用带随机盐的 scrypt 密码哈希及恒定时间摘要比较。

对应代码：`backend/app/core/input_security.py`、`backend/app/schemas/auth.py`、`backend/app/schemas/teacher.py`、`backend/app/core/security.py`。

### 2.2 登录及修改密码的既有保护

系统保留账号/IP 登录限速、不存在账号的占位哈希验证、统一登录失败提示，以及修改密码时校验原密码的规则。修改密码表单要求新密码和确认密码一致，长度为 10～128 个字符，且不能全部为空白或与原密码相同。

本次通过服务端会话校验，使退出、修改密码及管理员直接重置密码后，先前签发的令牌按第 3 节的规则失效。

## 3. 可撤销会话与身份校验

### 3.1 服务端会话

登录成功后，新增一条服务端会话记录，并在 JWT 中写入对应会话编号。每次认证同时验证：

- JWT 签名、算法、签发时间和到期时间。
- 固定签发方 `algopeer`、受众 `algopeer-web`，以及必需声明。
- 用户 ID、角色和会话编号的类型与格式；令牌长度不超过 4096 字符。
- 数据库中的用户角色与令牌角色一致。
- 会话存在、未撤销、未过期，且属于该用户。
- 会话保存的凭据指纹与用户当前密码哈希对应。

凭据指纹使用服务端密钥对密码哈希计算 HMAC-SHA256，不保存明文密码。

### 3.2 退出与改密

| 操作 | 系统行为 |
| --- | --- |
| 用户退出登录 | 调用新增的 `POST /api/auth/logout`，撤销当前服务端会话；成功后清除浏览器本地身份 |
| 用户修改密码 | 更新密码哈希，撤销该用户全部旧会话，为当前设备换发新令牌 |
| 管理员直接重置用户密码 | 后续认证时检测到凭据指纹变化，旧会话无法继续使用 |
| 已退出或旧令牌再次访问 | 返回 `401 UNAUTHENTICATED` |
| 多标签页并发登录、改密 | 旧请求返回时先比对当前本地令牌，避免覆盖新登录状态 |
| 退出撤销请求失败 | 前端保留当前身份并提示重试，避免显示退出成功而服务端会话仍有效 |

认证查询使用独立数据库会话，不提前启动业务事务，兼容学习分析的事务隔离设置和上传事务边界。

对应代码：`backend/app/api/routes/auth.py`、`backend/app/core/security.py`、`frontend/src/api/auth.js`、`frontend/src/App.vue`、`frontend/src/components/ChangePasswordDialog.vue`。

## 4. 写请求防重放与频率限制

### 4.1 时间戳与一次性随机编号

所有经过用户身份认证、且 HTTP 方法不是 `GET`、`HEAD`、`OPTIONS` 的请求，必须携带：

| 请求头 | 格式及规则 |
| --- | --- |
| `X-Request-Timestamp` | 10 位秒级 Unix 时间戳；允许过去 300 秒至未来 30 秒的范围 |
| `X-Request-Nonce` | 16 字节安全随机数编码成的 32 位小写十六进制字符串 |

前端用 `crypto.getRandomValues` 自动生成随机编号，用户不需要填写。登录接口通过来源检查和登录限速保护，不要求尚未建立的用户会话提供该证明。

服务端以“会话编号＋随机编号”作为数据库唯一键，原子插入并消费编号。相同会话重放同一编号时，只允许一次通过；并发重放同样受唯一键约束。

编号消费使用独立事务。即使后续业务处理失败并回滚，该编号也已经使用，不能重放。用户重新操作时，前端为新请求生成新编号；服务端不自动重试写操作。

该机制拦截相同编号的请求重放。持有有效令牌的请求方可以生成新编号，因此令牌传输使用 HTTPS，并继续受权限和频率限制约束。

### 4.2 频率参数

| 范围 | 当前限制 | 说明 |
| --- | --- | --- |
| 登录账号 | 10 次 / 600 秒 | 保留原有机制 |
| 登录来源 IP | 60 次 / 60 秒 | 保留原有机制 |
| 修改密码 | 10 次 / 600 秒 / 用户 | 保留已有独立限速 |
| 已认证 API | 600 次 / 60 秒 / 用户 | 本次增加 |
| 已认证写操作 | 120 次 / 60 秒 / 用户 | 本次增加 |
| 期末作业 ZIP 上传 | 10 次 / 600 秒 / 用户 | 本次增加 |
| 编程提交 | 10 次 / 60 秒 / 用户 | 本次增加 |

计数保存于 PostgreSQL，多个进程与服务重启共用。超过限制返回 `429` 并携带 `Retry-After`。过期计数会清理；请求编号保留 10 分钟，认证流量中以概率触发过期编号和会话清理。

### 4.3 客户端提示

| 错误码 | 含义 |
| --- | --- |
| `REQUEST_PROOF_REQUIRED` | 请求证明缺失或格式不符 |
| `REQUEST_EXPIRED` | 请求时间超出允许范围 |
| `REQUEST_REPLAYED` | 同一会话已使用该随机编号 |
| `API_RATE_LIMITED` | 已认证接口操作过于频繁 |
| `ORIGIN_NOT_ALLOWED` | 写请求来源不被允许 |
| `REQUEST_TOO_LARGE` | 请求体超出限制 |

对应代码：`backend/app/core/security.py`、`backend/app/services/login_throttle.py`、`frontend/src/api/client.js`、`frontend/src/api/errors.js`。

## 5. 浏览器、跨站请求与信息展示

### 5.1 XSS 与令牌发送范围

保留 Vue 文本插值的自动转义；增加恶意作业标题回归用例，验证 HTML、脚本和事件属性作为文本显示。

新增前端 CSP：脚本只允许本站来源，不允许行内脚本；禁止插件对象，禁止修改页面基准地址，表单限制为本站。图片允许本站、`data:` 与 `blob:`，媒体允许本站和 `blob:`。样式继续允许行内样式，以兼容当前界面。开发模式为本地热更新允许指定本地 WebSocket 来源，生产构建不包含该开发放行项。

前端 API 客户端只接受 `/api/` 开头的路径，拒绝外站地址、反斜杠、换行符和路径穿越片段。统一设置 `credentials: 'omit'`、`redirect: 'error'`，避免自动附带 Cookie 或跟随重定向发送请求。

### 5.2 Host、Origin 和 CORS

- 后端增加可信 Host 中间件，允许配置来源对应的主机及本地回环主机；`testserver` 仅在非生产环境允许。
- 对写请求检查 `Origin` 和跨站请求信息，只允许配置来源或当前同源来源。
- CORS 使用明确来源列表、HTTP 方法列表和请求头列表，关闭 Cookie 凭据跨域。
- 生产环境的 `CORS_ORIGINS` 必须为明确的 HTTPS 来源，不接受通配符和末尾斜杠。
- 生产环境关闭 `/docs`、`/redoc` 和 `/openapi.json`。

### 5.3 响应头

| 响应头 | 应用位置与设置 |
| --- | --- |
| `X-Content-Type-Options: nosniff` | 后端响应及前端开发/预览服务 |
| `X-Frame-Options: DENY` | 后端响应及前端开发/预览服务 |
| `Referrer-Policy: no-referrer` | 后端响应及前端开发/预览服务 |
| `Permissions-Policy` | 后端禁用摄像头、麦克风和定位权限 |
| `Cache-Control: private, no-store` | 后端响应禁止缓存 |
| `Content-Security-Policy` | 前端 HTML 构建产物含 CSP meta；开发/预览服务另发响应头；后端使用默认禁止资源加载的 API 策略 |
| `Strict-Transport-Security` | 生产后端识别为 HTTPS 时发送，期限 31536000 秒；TLS 反向代理同步配置 |

页面禁止嵌入还依靠响应头中的 `frame-ancestors 'none'` 与 `X-Frame-Options`，正式静态文件服务需配置这些响应头。CSP meta 不承担 `frame-ancestors` 的效果。

原有教师角色、学生身份、提交所有者及评委任务归属校验继续有效。本次增加真实登录、伪造角色声明和学生越权回归。原有输入错误不回显密码等输入值的处理继续保留。

对应代码：`backend/app/core/http_security.py`、`backend/app/main.py`、`backend/app/core/config.py`、`frontend/vite.config.js`、`frontend/src/api/client.js`。

## 7. ZIP、Office 与媒体文件

### 7.1 外层 ZIP

新增公共 ZIP 安全检查，供材料核验和匿名材料生成使用：

- 路径检查覆盖绝对路径、`..`、反斜杠、冒号/盘符、控制字符及 NFKC 全角路径绕过。
- 路径经 NFKC 和大小写折叠后检查重复，拒绝同形或大小写混淆的重复条目。
- 拒绝符号链接、加密条目和未允许的压缩编码；允许 ZIP Stored、Deflated。
- 最多 1000 个条目、单条目展开大小最多 500 MiB、总展开大小最多 1 GiB。
- 单条目展开大小与压缩大小之比不得超过 100。
- 清单中的材料路径使用同一安全路径校验。

材料按受控条目读取，不使用 ZIP 条目的路径直接解压到文件系统。视频处理使用应用生成的临时文件名。

### 7.2 嵌套 Office

PPTX、DOCX、XLSX 的内部 ZIP 独立检查：总展开大小最多 128 MiB、单条目最多 32 MiB、条目最多 2000 个，并执行路径、链接、重复和压缩比检查。

新增拒绝宏、ActiveX、嵌入对象、外部关系、XML DTD 和实体声明。外层 PPT 材料及匿名处理时需要一次读入内存的非视频材料限制为 64 MiB。

继续保留既有匿名处理：Office 去除 `docProps` 元数据，只处理清单声明的材料，以系统生成的名称重打包；安全或匿名检查失败时停止生成评阅材料。

### 7.3 图片和视频

- 图片解码前检查尺寸，像素数不超过 2000 万，再按原有流程重编码为 PNG。
- ffmpeg/ffprobe 的输入协议限制为 `file,pipe`。
- 匿名视频按扩展名指定 MOV 或 Matroska 解复用器；视频分析使用 MOV 解复用器处理 MP4，减少自动识别外部协议和格式的入口。
- 保留视频处理超时和元数据去除流程；处理异常按通用业务错误返回。

对应代码：`backend/app/core/archive_security.py`、`backend/app/schemas/student_submission.py`、`backend/app/services/student/material_check_service.py`、`backend/app/services/student/review_anonymization_service.py`、`backend/app/services/video_analysis.py`。

## 8. C++ 判题执行隔离

学生提交只进入后台队列，判题 worker 创建临时容器执行编译和测试，完成后清理容器及工作目录。

本次新增或强化：

1. 为不同提交分配不同 UID/GID（依据提交 ID），工作目录权限为 `0700`，隔离共享卷中的不同提交。
2. 丢弃全部 Linux capabilities，限制文件描述符为 128，关闭 core dump。
3. Docker 日志限制为 1 MiB、保留 1 个文件。
4. 编译增加文件大小限制 `ulimit -f 32768` 和 `-fmax-errors=10`，控制编译产物与错误输出。
5. worker 使用普通文件检查、`O_NOFOLLOW`、`O_NONBLOCK` 和读取大小上限，拒绝学生构造的符号链接、FIFO 或超大输出。
6. 每个测试前移除旧输入输出路径后再创建，防止上一测试把路径替换为链接。

保留并组合使用的既有容器限制包括：断网、只读根文件系统、非 root 执行、禁止提权、最多 64 个进程、1 CPU 限额、按题目限制内存、64 MiB 临时目录，以及单测试/总运行时间和输出限制。

默认配置为单测试 2000 ms、总运行 10000 ms、内存 256 MiB、程序输出 1 MiB、保存的编译错误输出 4 KiB；实际单测试时间与内存以题目配置为准。

Docker socket 由判题 worker 持有，学生代码容器不挂载该 socket。正式运行不可信代码时，判题 worker 和 Docker 引擎放在独立判题节点，应用、数据库和密钥放在业务节点。

对应代码：`backend/app/services/judge_runner.py`、`backend/app/core/config.py`，运行编排参考 `docker-compose.yml`。

## 11. 正式部署配置

### 11.1 配置项

| 配置项 | 交付要求 |
| --- | --- |
| `APP_ENV` | 设置为 `production` |
| `JWT_SECRET` | 独立随机值，至少 32 字符，替换开发示例值 |
| `INTERNAL_API_TOKEN` | 独立随机值，至少 32 字符，与 JWT 密钥不同 |
| `JWT_ALGORITHM` | 生产环境固定为 `HS256` |
| `DATABASE_URL` / `POSTGRES_PASSWORD` | 使用私有密码，连接字符串中的凭据按 URL 规则编码 |

| `TRUSTED_PROXY_IPS` | 在生产 Compose 启动命令中指定实际可信代理 IP，避免用 `*` |
| `VITE_API_BASE` | 优先使用同源 `/api` 代理；单独配置 API 地址时生产构建要求 HTTPS |

配置校验不通过时服务启动失败，防止带开发密钥或错误来源配置交付。

### 11.2 生产编排已有配置

`docker-compose.production.yml` 对后端设置只读根文件系统、丢弃 capabilities、禁止提权、最多 256 个进程、2 GiB 内存、2 CPU 限额、2 GiB 临时文件系统及独立材料持久化卷。Uvicorn 并发限制为 64、keep-alive 为 5 秒，关闭服务器名称响应头。

数据库和 Redis 不发布宿主机端口；后端只绑定宿主机 `127.0.0.1:8000`，由反向代理提供外部入口。

该生产 Compose 当前包含数据库、Redis 和后端。前端静态服务、TLS 反向代理及独立判题 worker 按交付环境另行部署；启动该文件不会自动部署全部这些组件。

### 11.3 交付部署步骤

1. 使用域名与有效 TLS 证书，部署构建后的 `frontend/dist`，同源代理 `/api`；学生访问正式静态站点。
2. 配置上表环境变量，启动后端并执行 `alembic upgrade head`，确认迁移链包含 `20261029_0018`。
3. 前端静态响应发送 `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、HTTPS 的 HSTS，以及包含 `frame-ancestors 'none'` 的 CSP 响应头。
4. 代理请求大小与后端上传上限协调，并设置连接、读写超时与连接数限制；仅信任实际代理源 IP，保证 IP 登录限速正确识别用户。
5. 部署匹配队列、数据库和工作卷配置的判题 worker，核对其 Docker socket 和节点隔离。
6. 教师和学生重新登录，并修改交付用初始密码；普通业务操作自动提供时间戳和随机编号。
7. 备份数据库、材料存储及 `storage/.private/video-ai.key`；私有密钥目录不提供静态下载，实际密钥与密码通过独立渠道交接。
