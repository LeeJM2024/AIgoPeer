# 答辩演示流程

日期：2026-10-19。目标：约十五分钟展示“教师配置 → 学生提交 → 跨班匿名评审 → 教师处理 → 发布查分”。这是可执行的演示脚本，不是本日整场演示已执行的声明。代码版本、启动和证据见 [最终交付说明](最终交付说明-20261019.md)。

## 1. 提前准备四份作业

完整流程存在真实截止和五人评分约束，现场使用四份新作业展示不同阶段，避免等待整场评分或修改冻结规则。标题可加当天演示批次，界面/接口返回的 ID 记入表格，不固定抄用验收环境 ID。

| 作业 | 开始演示时的条件 | 用途 | 现场 ID |
| --- | --- | --- | --- |
| DEMO-PROG | 新两班编程题草稿，含公开/隐藏用例；截止在演示结束之后 | 现场发布、学生看题和真实 AC | 待填 |
| DEMO-UPLOAD | 新期末作业已发布，双向各五人配置完成，提交和评审截止均在未来 | 认领、缺视频纠错、当前版本与历史 | 待填 |
| DEMO-REVIEW | 已真实上传两班各至少一份有效作品；提交已自然截止；评审截止未到；任务已初始化 | 下载匿名包、现场完成一份正式评分 | 待填 |
| DEMO-PUBLISH | 另一份已真实上传、评分及聚合就绪的期末作业，教师分已锁定，异常/必要最终复核已处理 | 发布前检查、发布、学生查分与教师导出 | 待填 |

两组 Panel 方向必须相反：一班作品由二班五人评，二班作品由一班五人评。最小完整准备可只让两班各一名作者上传，每份收五份正式评分，共十份评审；评审人同时作为本班作者是允许的，但不能自评或跨过资格校验。

DEMO-REVIEW 的短时展示可保留一份待评任务，其余先完成；它与 DEMO-PUBLISH 是不同作业，现场一次新评分不会扰乱已准备的发布条件。下载必须成功后才开始计时，评分如触发风险按真实规则处理，不伪造服务端时间或修改数据库状态。

准备阶段给上传留足时间：先设置未来提交截止并完成材料，再等待自然截止生成任务；评审截止覆盖准备和演示。不要对已发布作业改规则，也不要复用旧验收成绩来演示重新发布。

## 2. 演示前检查

- 记录 `git rev-parse HEAD`；API 健康、Redis、worker 和判题镜像可用，浏览器无遗留教师/学生会话混用。
- 教师、作者、另一班评审人使用独立浏览器配置或无痕窗口。标签按角色命名，切换时确认页面右上角身份。
- 在教师页核对四份作业实际阶段、两班名单、Rubric 与自然截止；先验证 DEMO-REVIEW 可以下载，DEMO-PUBLISH 发布检查无阻断。
- 按 [样例说明](../samples/README.md) 准备两个重命名后的 ZIP、清单及求和代码。样例视频是四秒蓝色静音片段，只用来演示系统处理，讲解时直接说明。
- 录屏只用合成身份。关闭私有配置、令牌、数据库连接串和教师内部证据标签，学生视角不展示教师原分或风险记录。

以新种子库的 D101、姓名“1班学生01”、认领 R01 为例，制作本次上传副本：

```powershell
$demoDir = Join-Path (Get-Location) ('tmp/demo-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path (Join-Path $demoDir 'valid'),(Join-Path $demoDir 'missing-video') | Out-Null
Copy-Item -LiteralPath 'samples/demo-valid.zip' -Destination (Join-Path $demoDir 'valid/D101_1班学生01_R01.zip')
Copy-Item -LiteralPath 'samples/demo-missing-video.zip' -Destination (Join-Path $demoDir 'missing-video/D101_1班学生01_R01.zip')
```

其他账号必须按实际姓名和已认领编号调整。两包外层文件名相同、目录不同；包内路径不变。首次进入“认领并上传”时选择 R01；若该账号在本作业已认领其他主题，就使用对应编号，不能现场改既有认领。

## 3. 十五分钟主线

| 时间 | 操作者、页面及动作 | 应看到的结果 | 建议讲解 |
| --- | --- | --- | --- |
| 0:00—1:00 | 展示 main 的 commit、登录入口和教师工作台 | 身份明确、真实数据可读取 | 项目把提交、互评、教师决策和成绩追溯串成闭环；接下来使用四份不同阶段作业 |
| 1:00—3:00 | 教师 `/teacher/assignments` 打开 DEMO-PROG，确认题目与未来截止后发布；作者进入 `/student` 选该题，提交 samples/demo-sum.cpp | 发布后可见；题面仅有公开样例；排队/运行后显示“通过”及用例统计 | 隐藏用例只在服务端；程序运行时间与 Docker 管理时间分开，500ms 题目不靠提高限制绕过误超时 |
| 3:00—6:00 | 作者进入 DEMO-UPLOAD“认领并上传”，认领主题，按下表填清单；先传缺视频包，再传完整包，刷新并打开历史 | 第一版 INVALID / VIDEO；第二版 VALID；当前版与旧版检查分开保存 | 完整性通过不等于内容质量合格；纠错形成新版本，旧结果仍可追溯 |
| 6:00—9:00 | 切评审人，在 `/reviewer/tasks` 打开 DEMO-REVIEW；点击“下载匿名材料并开始评审”，查看匿名包，填写全部 Rubric 和评语，提交一份评分 | 仅本人任务；下载包使用通用材料名；提交后待办消失，重复提交受限 | 固定五人跨班任务由教师配置生成，不是自由领取；开始时间由成功下载决定 |
| 9:00—12:00 | 切教师，明确展示另一份 DEMO-PUBLISH；在评分工作台看发布检查、锁定版本及处理记录，然后发布；在“成绩统计与导出”导出 | 真实发布成功；导出包含成绩来源、权重和版本 | 普通作品按 60% 教师 / 40% 五人聚合；HIGH 使用首次初评教师的复核最终分，算法不替教师做最终处罚 |
| 12:00—14:00 | 切 DEMO-PUBLISH 作者，从学生作业进入成绩页；再切另一学生查看本人结果或空状态 | 只看本人最终结果、匿名评语、教师反馈与 Rubric 说明；不出现内部具体评分和身份 | 页面、接口和数据权限共同约束身份，不能通过改查询参数查看别人结果 |
| 14:00—15:00 | 打开已归档的范围账、修复报告及九项 main 冒烟结果 | 实测数字、版本和证据可对应 | 113 项范围账来自原验证加定向复验；报告区分真实服务、受控测试与未执行的现场步骤 |

素材清单填写值（对两个包相同）：

| 字段 | 值 |
| --- | --- |
| PPT / 视频 / README | slides.pptx / video.mp4 / README.md |
| 源码路径 | src/main.cpp |
| 三个例题页码 | 2,3,4 |
| 测试 1 | tests/1.in / tests/1.out |
| 测试 2 | tests/2.in / tests/2.out |
| 测试 3 | tests/3.in / tests/3.out |

页面结果通过实际轮询更新。判题页面轮询间隔约两秒，不把后端已完成后短暂仍显示“运行中”当作失败；材料检查超出自动等待可点刷新读取，不必重复上传。

## 4. 有余量时扩展展示

仅对 DEMO-PROG 的求和题使用以下样本；源文件也可直接复制 [正确代码](../samples/demo-sum.cpp)。

| 想展示的结果 | 提交代码 | 前提 |
| --- | --- | --- |
| WA | `#include <iostream>` 换行后 `int main(){std::cout<<0;}` | 测试集中至少有一例和不为零 |
| CE | `int main( { invalid syntax }` | worker 与编译器就绪 |
| RE | `#include <cstdlib>` 换行后 `int main(){std::abort();}` | 展示非正常退出 |
| TLE | `int main(){for(;;){}}` | 使用正常受限判题，不停止共享服务 |

可以再展示编程旧版结果、草稿恢复、期末旧版 INVALID、无任务学生无评审入口、学生误入教师返回地址自动回学生工作区。若现场没触发 PENDING、并发 401 或高风险场景，说明已有归档证据，不把未现场执行记成现场通过。

遇到 SYSTEM_ERROR，先保留提交 ID 并检查环境；遇到未到提交截止、评审尚未收齐、教师分未锁定或异常未处理，按页面说明完成条件。不能通过改数据库、清空限流计数或伪造结果来维持固定演示顺序。时间不足时展示事先准备的真实记录，并说明展示对象已切换。

## 5. 现场记录与结束

| 实际 commit / 环境 | 步骤 / 作业及提交 ID | 实际结果 | 证据路径 | 待办负责人 |
| --- | --- | --- | --- | --- |
| 待填写 | 如主线 3，作业/版本/提交 | 通过 / 失败 / 未执行 | 脱敏截图、导出或响应 | 教师 / 学生判题 / 算法 / 环境 |

结束后保存记录及导出，退出演示账号。保留数据库与材料卷用于追溯，需要停服务时使用 `docker compose stop`。本次文档和技术样例已经准备，新的现场答辩及新机器首次启动仍由操作者按清单执行并记录。
