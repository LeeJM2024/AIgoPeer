# AlgoPeer：跨班公平随机评审与稀疏贝叶斯聚合最终方案

版本：`2.0.0`

状态：算法设计基线

适用范围：两个教学班之间的期末大作业匿名互评。班级人数可以不同，评审任务由系统按约束随机生成，不再使用固定评审 Panel。

> 本文是固定五人 Panel 方案的升级版。核心思想是：评审关系跨班随机生成，评审图保持稀疏；每份作品仍默认获得 5 份独立同伴评分，只有评分完整后才进入聚合和成绩发布流程。

## 1. 目标与原则

系统需要同时满足四个目标：

1. **跨班隔离**：学生只评另一班的作品，降低熟人关系对评分的影响。
2. **公平随机**：评审关系由可复现的随机分配生成，不由教师手工指定固定评委。
3. **稀疏高效**：每名学生只评少量作品，不构造“每个人评所有作品”的稠密矩阵。
4. **可解释聚合**：对评审者的严宽偏差、评分稳定性和单次异常评分进行建模，向教师展示证据，而不是自动处罚学生。

基本成绩政策：

```text
低风险或已确认的普通作品：
最终分 = 教师第一次评分 × teacher_weight
       + 同伴聚合分 × peer_weight

默认 teacher_weight = 0.60
默认 peer_weight = 0.40

高风险作品：
最终分 = 同一名教师查看完整证据后录入的最终复核分
```

教师可以在发布作业时修改两个权重，但必须满足：

```text
0 <= teacher_weight <= 1
0 <= peer_weight <= 1
teacher_weight + peer_weight = 1
```

高风险作品的第一次教师分、所有原始同伴评分、聚合分、风险证据和最终复核分全部保留，便于审计。

## 2. 评审关系模型

### 2.1 二部稀疏图

将一次作业的有效提交和评审任务表示为二部图：

```text
左侧：有效作品 submission
右侧：有资格的学生 reviewer
边：reviewer 被分配评阅 submission
```

只允许跨班边：

```text
submission.class_id != reviewer.class_id
```

默认每份作品需要 `K = 5` 名不同评审人。评审边总数约为：

```text
有效作品数 × K
```

而不是所有评审人和所有作品的笛卡尔积，因此评分矩阵是稀疏的。两班人数不需要相等，例如一班约 100 人、二班约 40 人时，系统通过负载均衡让二班学生承担较多但受上限约束的评审任务。

### 2.2 评审资格

评审人必须满足：

- 当前属于作业配置的一个班级；
- 目标作品属于另一个班级；
- 账号有效且没有被教师禁用评审资格；
- 对同一作品尚未获得另一条重复任务；
- 不是目标作品作者；
- 具备完成本次评审所需的学生身份。

系统不公开作品作者和其他评审人的身份。评审人只能看到自己被分配到的匿名材料。

## 3. 跨班公平随机分配

### 3.1 输入

分配器输入：

```text
assignment_id
generation_id
有效提交快照
班级成员快照
每份作品目标评审数 K，默认 5
每名学生评审上限和软目标
随机种子 seed
```

教师可以在提交截止前手动开始评审。此时系统只对当前快照中的有效提交生成任务，不需要先结束提交。

### 3.2 分配步骤

1. 固定当前有效提交和班级成员快照，生成 `generation_id`。
2. 按班级分别建立候选评审池，只保留另一班的合格学生。
3. 使用 `seed = H(assignment_id, generation_id, teacher_seed)` 初始化可复现随机序列。
4. 对每个目标班的作品随机打乱候选评审人顺序。
5. 优先选择当前任务数较少的评审人；任务数相同时使用随机顺序打破平局。
6. 为每份作品选择 `K` 名不同评审人，禁止同班、重复和自评。
7. 进行交换改良，使评审任务数尽量均衡；目标是最小化最大负载与平均负载的差距。
8. 对每条任务写入生成批次、随机种子和分配快照哈希。

分配目标可以表示为：

```text
minimize  max_r(load[r]) - min_r(load[r])
          + λ × Σ_r |load[r] - target_load[r]|
```

其中 `target_load[r]` 根据另一班有效作品数、`K` 和合格评审人数计算。负载均衡是软目标，跨班、每份作品 `K` 名不同评审人和禁止自评是硬约束。

### 3.3 分配失败

如果某一方向的合格评审人数不足以满足每份作品 `K` 名不同评审人，系统不得偷偷降低评审数，也不得把任务分配给本班学生。教师端应显示缺口：

```text
REVIEWER_CAPACITY_INSUFFICIENT
```

教师可以补充合格学生、降低本次作业的目标评审数，或重新生成任务。变更会产生新的 `generation_id`，旧批次保留审计记录。

### 3.4 提交截止前开始评审

评审可以早于提交截止开始：

- 已生成批次只覆盖生成时的有效提交快照；
- 后续新提交不会悄悄插入已经发出的任务；
- 教师可以在发布成绩前重新生成一个新批次，补入新增提交；
- 新批次替代旧批次，但旧批次、任务状态和评分记录保留；
- 一旦成绩发布或教师锁定最终复核分，不允许重新分配或重新聚合。

## 4. 稀疏 Bayesian 聚合模型

### 4.1 观测变量

对每条已提交评审边记录：

```text
x[r,s,k]       评审人 r 对作品 s 的第 k 个 Rubric 项归一化评分
theta[s,k]     作品 s 在第 k 项的潜在真实分
bias[r]        评审人 r 的长期严宽偏差
sigma[r]       评审人 r 的评分噪声
pi[r]          评审人 r 的异常评分先验概率
z[r,s,k]       当前评分是否为异常观测
```

只对稀疏图中实际存在的评审边建模。缺失边不是零分，也不参与平均。

归一化：

```text
x[r,s,k] = score[r,s,k] / max_score[k]
```

### 4.2 观测模型

```text
z[r,s,k] ~ Bernoulli(pi[r])

当 z = 0：
x[r,s,k] ~ TruncatedNormal(theta[s,k] + bias[r], sigma[r]^2, 0, 1)

当 z = 1：
x[r,s,k] ~ Uniform(0, 1)
```

先验使用收缩策略，避免一个评审人只评很少作品时被过度解读：

```text
theta[s,k] ~ Normal(0.50, 0.25^2)
bias[r]     ~ Normal(0, 0.15^2)
sigma[r]    >= 0.05
pi[r]       ~ Beta(1, 20)
```

评审人画像只使用其已完成的不同作品数统计，不按 Rubric 行数重复计算。达到至少 3 份不同作品后才学习个人画像；不足时使用群体先验并标记 `learned=false`。

### 4.3 MAP-EM 推断

首版使用确定性的 MAP-EM，而不是随机 MCMC，确保演示、测试和复算结果一致：

1. 使用先验和逐项中位数初始化 `theta`。
2. E 步计算每条评分的异常后验概率：

   ```text
   p_anomaly[r,s,k] = P(z[r,s,k] = 1 | all observed scores)
   ```

3. 根据异常概率和评分噪声计算有效权重：

   ```text
   w[r,s,k] = (1 - p_anomaly[r,s,k]) / max(sigma[r]^2, sigma_min^2)
   ```

4. M 步更新作品潜在分、评审偏差、评审噪声和异常先验。
5. 对偏差做零均值约束，防止作品真实分和评审偏差互相吸收。
6. 参数变化小于 `1e-6` 或达到 100 次迭代时停止。

逐项潜在分的实现近似为：

```text
theta[s,k] = clip(
  (lambda * theta_prior_mean
   + Σ_r w[r,s,k] * (x[r,s,k] - bias[r]))
  / (lambda + Σ_r w[r,s,k]),
  0, 1
)
```

### 4.4 稀疏评分的完整性要求

稀疏指评审关系稀疏，不代表评分可以缺失后直接发布：

- 作品只有少于 `K` 份已提交评分：不生成正式聚合，状态为 `INSUFFICIENT_REVIEWS`；
- 作品达到 `K` 份完整评分后，才进入正式聚合；
- 某评审人没有评阅某作品不算缺失错误；
- Rubric 项缺失、重复、满分不一致或分数越界时，拒绝本次聚合；
- MAP-EM 不收敛时使用逐项中位数作为明确回退，并将运行标记为失败或回退，不能伪装成 Bayesian 后验结果。

## 5. 聚合分、置信度与风险

Bayesian 聚合逐项分：

```text
aggregate_score[s,k] = round(theta[s,k] * max_score[k], 2)
aggregate_total[s]   = Σ_k aggregate_score[s,k]
```

同时保存逐项中位数，作为鲁棒基线和解释参照。近似标准误和区间：

```text
SE[s,k] = sqrt(1 / (lambda + Σ_r w[r,s,k]))
CI[s,k] = max_score[k] × clip(theta[s,k] ± 1.96 × SE[s,k], 0, 1)
confidence[s,k] = 1 - min(1, CI_width_normalized / 0.20)
```

### 5.1 高风险硬规则

以下任一条件成立，作品进入 `HIGH`，停止直接采用同伴聚合分作为最终成绩：

1. 同一 Rubric 项中，四名评审人分数集中而一名评审人明显离群：

   ```text
   span(other four) <= 0.15
   abs(outlier - median(other four)) >= 0.30
   ```

2. 某条评分的 `p_anomaly >= 0.95`。
3. Bayesian 潜在分与逐项中位数的归一化差异至少为 `0.15`。
4. 可信区间宽度至少为 `0.20`。

任一 Rubric 项触发即可升级整份作品。四人集中、一人异常的判断只使用该作品实际获得的评审边，不要求所有学生评阅所有作品。

### 5.2 行为证据

以下信号用于辅助教师判断，不单独认定学生恶意：

- 评审耗时明显短于同批次中位数；
- 评语去空白后少于 30 个字符；
- 多个 Rubric 项集中给出相同分数，归一化熵过低；
- 上述行为信号同时出现两项以上。

系统保留原始评分和行为证据，不自动修改评分、不自动处罚评审人，也不向评审人泄露其他人的分数。

### 5.3 风险状态

```text
LOW     没有硬异常，证据充分
MEDIUM  存在多个行为信号或风险分达到阈值，等待教师确认
HIGH    命中硬规则，必须进入教师最终复核
```

## 6. 教师最终处理

教师端对每份作品展示：

- 第一次教师评分；
- 5 份同伴原始评分及评语；
- Bayesian 聚合分和逐项中位数；
- 置信区间、风险等级和异常证据；
- 评审任务批次、算法版本和输入快照。

高风险作品进入：

```text
ESCALATED_FOR_TEACHER_FINAL_REVIEW
```

教师只需录入一次最终复核分即可，不需要重新填写整套 Rubric。教师提交后：

```text
final_score = teacher_final_review_score
final_grade_source = TEACHER_FINAL_REVIEW
```

低风险和中风险作品按教师明确的权重计算；中风险也必须经过教师确认后才能发布。教师可以驳回风险提示，评语和理由为可选字段；系统必须保留确认或驳回的审计记录。

## 7. 可复现、可审计与隐私

每次生成和聚合都记录：

```json
{
  "assignment_id": 1,
  "generation_id": "...",
  "algorithm_name": "sparse_cross_class_bayesian",
  "algorithm_version": "2.0.0",
  "random_seed": 20261029,
  "review_count_per_submission": 5,
  "input_hash": "sha256(...)"
}
```

输入哈希覆盖班级成员快照、有效提交快照、任务分配、评分、Rubric 满分、任务状态和聚合参数。相同快照、相同种子和相同参数必须得到相同的任务关系和聚合结果。

作者身份、评审人身份和异常标记仅对有权限的教师可见。学生只能看到自己的提交、自己的评审任务和发布后的反馈。

## 8. 论文依据与项目工程决策

论文依据：


1. Zarkoob et al., AAAI 2023, *Better Peer Grading through Bayesian Inference*：潜在真实分、评分者偏差、可靠性和 Bayesian 同伴评分。
2. Stelmakh, Shah, Singh, AAAI 2021, *Catch Me if I Can: Detecting Strategic Behaviour in Peer Assessment*：同伴评审中的策略性行为检测。
3. Agarwal et al., ICML 2020, *Rank Aggregation from Pairwise Comparisons in the Presence of Adversarial Corruptions*：在污染或异常观测下进行鲁棒聚合的建模启发。

项目自行设定的工程参数：

- 每份作品默认 5 名跨班评审人；
- 评审关系使用带负载均衡的可复现随机分配；
- 教师初评分与同伴聚合分默认 60%/40%，发布时可修改；
- 四人集中一人离群、后验异常概率、区间宽度等风险阈值；
- 评审人画像的最小学习样本数；
- 任务生成批次、快照、重生成和成绩发布冻结规则。

随机分配、负载均衡、风险阈值和成绩权重属于本项目的工程设计，不能表述为上述论文直接给出的定理或固定参数。

## 9. 与当前代码的迁移边界

仓库中的旧版 `algorithm/ALGORITHM_SPEC.md` 和相关数据库结构仍记录“固定五人 Panel”实现。要让系统真正采用本文方案，需要同步升级：

1. 将固定 `review_panel` 改为按 `generation_id` 保存的随机任务批次；
2. 删除“一个 Panel 必须恰好五名固定评审人”的数据库约束；
3. 增加跨班候选池、任务负载和随机种子记录；
4. 将聚合服务从 Panel 全量输入改为稀疏评分边输入；
5. 保留每份作品达到 5 份完整评分后才聚合、发布前教师复核等业务规则；
6. 更新接口、前端教师任务生成页面、测试数据和验收文档。

在上述迁移完成前，本文作为目标算法设计文档，不应宣称当前线上代码已经完成随机稀疏评审升级。
