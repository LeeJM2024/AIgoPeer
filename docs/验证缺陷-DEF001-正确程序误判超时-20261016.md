## 复现

教师创建并发布两数求和编程作业，设置合法时间限制 **500ms**、内存 128MiB、1 个公开及 3 个隐藏用例。合成学生 VERIFY-A01 通过真实代码提交 API 提交：

```cpp
#include <iostream>
int main() {
    long long a, b;
    std::cin >> a >> b;
    std::cout << a + b << "\n";
}
```

公开输入 `1 2`，预期输出 `3`。另有负数、零和较大数的合法隐藏输入。

本轮 FLOW 对象：assignment_id=1；首份正确代码 submission_id=1，重复正确代码 id=2，正确且带尾随空白 id=7。对象 ID 仅用于本轮，不作为脚本固定前提。

## 计时诊断

在同一真实 worker、同一判题镜像、同一工作卷，以相同正确源码编译并执行 `1 2`，使用容器内 `/usr/bin/time` 与调用外层 monotonic 分别计时：

```json
{
  "returncode": 0,
  "stdout_file": "3\n",
  "inner_measurement": "INNER_SECONDS:0.00\n",
  "outer_container_call_ms": 612.331,
  "configured_problem_limit_ms": 500
}
```

这是诊断执行，未写入假判题结果或修改原提交。内层时间精度为 0.01 秒；`0.00` 不表示绝对零耗时，但足以区分本次观测中的程序耗时和 612ms 的容器调用耗时。

静态定位：`backend/app/services/judge_runner.py:198` 在 `_run_container` 前开始计时，209 行读取返回后的耗时，233 行用此值与题目时间限制比较。`_run_container` 包含创建、等待、日志读取及 finally 中的容器删除。因此容器调用开销进入学生代码的用例时限。总时限的 monotonic 检查也需要成员 2 一并确认其与题目资源限制的语义。
