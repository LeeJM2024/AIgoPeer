| 学生材料与代码 | 成员 2 | 准备合成正确代码与错误代码；期末完整 ZIP、缺视频 ZIP、对应页面清单字段；材料正文不含作者身份 |

用新作业组织演示，或先核对旧作业真实阶段与截止时间。不要改已冻结的作业规则来重演上传；`VALID` 不代表作品已分配评审任务，已分配也不代表当前阶段允许评分。

本地工具版本要求：Python 3.11+、Node.js 20+（CI 使用 22）和已启动的 Docker Desktop；前端测试依赖由 `npm ci` 安装。

第一次搭建空开发环境时，在仓库根目录执行：

```powershell
Copy-Item -LiteralPath '.env.example' -Destination '.env'
# 编辑 .env，替换数据库密码和 JWT 密钥；DATABASE_URL 与数据库配置保持一致。
docker compose up -d --build
docker compose ps
Invoke-RestMethod 'http://127.0.0.1:8000/api/health'
```

上述复制仅适用于没有 `.env` 的新环境。已有环境沿用现有配置，先查服务端口和数据归属，不重新初始化或覆盖配置。代码仓库的开发启动说明见 [README](../README.md)；生产部署由部署负责人另行验收。

前端在单独终端执行：

```powershell
Set-Location frontend
npm ci
# 默认代理到 8000；已有环境在此填写实际后端地址。
$env:API_PROXY_TARGET = 'http://127.0.0.1:8000'
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

浏览器打开 `http://127.0.0.1:5173/login`。使用管理员提供的合成身份；已有账号及密码不写入本清单。

可选：新本地开发库可执行 `docker compose exec backend python scripts/seed_demo.py`，生成 README 所述演示账号和数据。种子期末数据是直接准备的评分阶段记录，没有真实上传材料，**不能据此演示完整上传或匿名材料下载**。仍需教师新建期末作业、学生实际上传；已有业务库不要把种子当成重置工具。

### 期末材料样例约定

ZIP 文件名为当前登录人的 `学号_姓名_认领知识点编号.zip`，最大 500 MiB。ZIP 内路径使用相对路径和 `/`，页面字段必须与实际文件一致。例如：

```text
slides.pptx
video.mp4
README.md
src/solution.cpp
tests/1.in
tests/1.out
tests/2.in
tests/2.out
tests/3.in
tests/3.out
```

页面填写 `slides.pptx`、`video.mp4`、`README.md`、`src/solution.cpp`，例题页码如 `2,3,4`（三页必须真实存在），以及上述三组测试路径。PPT 建议 8–12 页，视频须为可处理的 MP4。缺视频样例只移除 `video.mp4`，页面仍声明该路径，便于观察 `VIDEO` 缺失项。正文不放姓名、学号或其他身份线索；原文件名与内容匿名化是不同检查。

## 2. 路径一：教师发布 → 学生收到 → 编程提交与判题

| 步骤 | 操作者与操作 | 预期及应记录证据 |
| --- | --- | --- |
| A1 | 教师在 `/teacher/assignments` 创建编程题并完成发布 | 草稿阶段学生列表没有该作业，发布后适用班学生可见；截图记录标题和截止时间 |
| A2 | 学生登录 `/student`，进入该题 | 题面和公开样例可见；响应不包含隐藏用例 |
| A3 | 在页面提交正确的 C++17 两数求和程序 | 从排队/运行进入 AC；记录版本和提交 ID |
| A4 | 在页面分别提交错误答案、编译错误、异常退出、无限循环程序 | 对应 WA、CE、RE、TLE；不能把 Docker/Redis 故障当成这些代码结果 |
| A5 | 查看提交页下方历史，选择早期错误版本 | 仅旧版判题详情变化，编辑器草稿和当前结果不被替换；历史每页 5 条，至少 6 次提交可检查翻页 |
| A6 | 编辑一段未提交草稿后重载页面 | 本浏览器恢复该账号/作业草稿；最近提交结果从服务端恢复，不将历史源码当草稿 |
| A7 | 切换同班未提交学生，再切回作者 | 另一账号没有作者历史或草稿；作者原有记录保留 |
| A8 | 使用另一个已截止的演示作业 | 可以读取本人既有结果和历史，实际上传被后端拒绝；外班学生不能读取非适用作业 |

建议代码只用于“两数求和”演示题：AC 输出 `a+b`；WA 固定输出 `0`（用例需有非零和）；CE 用无法编译的语法；RE 使用 `std::abort()`（包含 `<cstdlib>`）；TLE 使用持续运行的无限循环。实际结果以 worker 返回为准，不伪造状态。

`SYSTEM_ERROR` 表示基础设施异常，由环境维护人检查 Redis、worker、镜像和 Docker；不以此扣分。无需为展示这个状态故意停掉共享服务。

## 3. 路径二：期末认领 → 上传纠错 → 当前恢复与历史

| 步骤 | 操作者与操作 | 预期及应记录证据 |
| --- | --- | --- |
| B1 | 教师发布期末作业；学生从 `/student` 进入“认领并上传” | 作业信息和认领选项可读取；学生认领后显示对应知识点 |
| B2 | 页面填写清单，上传缺视频 ZIP | 创建第一版；检查完成为 INVALID，缺失项包含 VIDEO；不具备有效作品评审条件 |
| B3 | 页面上传完整 ZIP | 版本增加，检查通过为 VALID；检查提示与硬性缺失分开显示，不把完整性通过说成内容质量合格 |
| B4 | 重载页面，再点“刷新提交状态” | 当前版本/检查可从服务器恢复；不需要重新选择文件或再次提交 |
| B5 | 在截止前累计至少 6 版，历史翻到下一页查看第一版 | 只显示本人版本，每页 5 条、最新在前；第一版仍保留原检查结果，不用 SUPERSEDED 覆盖 INVALID |
| B6 | 查看旧版检查后，再从上方上传一版 | 当前版本增加，历史回第一页；旧详情保持独立，表单不会因选择历史被改写 |
| B7 | 如遇旧版 PENDING，等待再点“刷新此版本结果” | 旧详情只在手动点击时重读，不自动轮询或重新检查；若无 PENDING，记“现场未触发”，引用组件测试覆盖 |
| B8 | 切换同班另一学生 | 只看到自己的当前提交/历史；没有提交时显示空状态 |
| B9 | 等自然截止，或打开另一个已截止且有提交的作业 | 禁止上传，当前记录和历史仍可读取；截止拒绝不能删除原当前版本 |

当前材料检查会短时轮询（约 40 秒），超时或失败可手动刷新读取状态。页面没有提供重新执行后台检查的能力。跨截止收包的原子拒绝、回滚和新 ZIP 清理由后端测试覆盖，现场未复现时不要标为现场通过。

## 4. 路径三：指定匿名互评 → 教师处理 → 本人查分

可接续路径二：等提交截止后进入评分阶段；时间有限时，另备一份已真实上传、已截止且任务就绪的作业。不要用种子的无材料记录替代实际材料链路。

| 步骤 | 操作者与操作 | 预期及应记录证据 |
| --- | --- | --- |
| C1 | 教师在作业详情触发初始化；成员 3 核对任务生成 | 两个 Panel 按对方班固定 5 人分配；只为当前有效作品生成任务 |
| C2 | 无有效任务学生登录 `/student` | 没有评审入口；直接请求任务列表拒绝，不能主动领取任务 |
| C3 | 指定评审人登录，进入 `/reviewer/tasks` | 只列本人任务，以匿名编号区分；没有作者身份、教师分、聚合分或其他评审记录 |
| C4 | 点击“下载匿名材料并开始评审”，检查下载包 | 下载成功后任务进入进行中；包内通用材料名，不下发原 ZIP；服务端记录开始时间 |
| C5 | 按所有 Rubric 维度评分，填写评语并提交 | 每维度不超满分，必须完整填写；成功后从默认待办消失，同一任务不可再次提交或修改 |
| C6 | 同一作品其余 4 名指定评审人完成评分；双向班级分别完成 | 每份作品收齐 5 份正式评分；少一份时不能正式聚合，以教师页面/接口验证 |
| C7 | 成员 1/3 配合完成聚合，教师评分、锁定、异常处理和需要的最终复核，再发布 | 这些操作由相应负责人执行；不能为演示绕过风险/复核阻断；记录真实发布结果 |
| C8 | 发布前后分别用作者打开 `/student/assignments/{id}/grade` | 发布前提示暂未发布；发布后仅本人最终总分、匿名评语、教师反馈和 Rubric 说明；不显示内部具体评分或风险 |
| C9 | 切换另一学生并检查其本人结果 | 不能读取原作者结果；若自己也有成绩，只返回自己的成绩 |

匿名化对可处理元数据及可检测身份线索做限制，不替代人工检查所有材料内容。截图和录屏使用合成身份，学生侧截图不夹带教师内部评分页。

## 5. 回归入口及已有证据

```powershell

python -m ruff check backend tests
# 由测试环境维护人设置 TEST_DATABASE_URL：专用空 PostgreSQL 测试库。

git diff --check
```

前端：`npm ci`、`npm test`、`npm run build`。完整数据库回归前先确认目标库不含业务数据，且 `public.users` 和 `public.alembic_version` 均不存在；测试账号须能建/删测试 schema。不能将现有 QA 或业务库连接串用于 pytest。未配置数据库时相关测试会跳过，不能记为通过。
