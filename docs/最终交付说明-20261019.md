## 3. 从新克隆启动本地演示

前提：Git、已启动且使用 Linux 容器的 Docker Desktop / Compose、Node.js 20+（建议沿用项目 CI 的 22）、npm。只有在主机执行 Python 测试时才另需 Python 3.11+。首次构建需要能下载镜像及依赖。

在仓库根目录操作。已有克隆先保证工作区干净，再更新；新目录可执行：

```powershell
git clone https://github.com/LeeJM2024/AIgoPeer.git
Set-Location AIgoPeer
git rev-parse HEAD

if (-not (Test-Path -LiteralPath '.env')) {
    Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
```

在启动前编辑 .env：POSTGRES_PASSWORD 与 DATABASE_URL 中的密码必须相同，数据库主机使用 Compose 服务名 db；JWT_SECRET 和 INTERNAL_API_TOKEN 分别设置不同的随机长字符串，建议各至少 32 字符。保持本地 `APP_ENV=development`、`AI_VIDEO_ENABLED=false`。不要覆盖已有 .env，也不要把已有数据卷当成空库；POSTGRES_PASSWORD 的新值不会自动修改旧数据库内部密码。

默认占用 5432、6379、8000 和前端 5173。先确认这些端口没有被别的项目使用。若另设项目名，还必须为 JUDGE_WORK_VOLUME 配置独立卷名，并调整端口/存储；只改 Compose 项目名不能隔离显式命名的判题卷。

```powershell
docker compose config --quiet
docker compose up -d --build
docker compose ps -a
Invoke-RestMethod 'http://localhost:8000/api/health'
docker compose exec backend alembic current
docker compose exec redis redis-cli ping
docker compose logs --tail 30 judge-worker
```

预期：健康接口成功，迁移头为 20261010_0008，Redis 返回 PONG，worker 已启动队列消费；judge-image 构建服务正常退出为 0 是预期，不要求它常驻。后端和 worker 需同时运行，只有 API 可用并不代表可以判题。可打开 `http://localhost:8000/docs` 查看实际接口。

新本地演示库需要首次账号时可执行：

```powershell
docker compose exec backend python scripts/seed_demo.py
```

种子仅用于新开发演示库，production 禁止执行。它提供教师、两班各十名学生和部分预置作业；已有同名账号的密码不会重置。种子的期末评分记录没有实际材料文件，**演示上传、匿名包下载及真实评分闭环必须新建作业并真实上传**，不能用种子记录代替。

另开 PowerShell 终端，在 frontend 目录启动：

```powershell
Set-Location frontend
npm ci
$env:API_PROXY_TARGET = 'http://127.0.0.1:8000'
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

打开 `http://localhost:5173/login`。前端实际后端地址不同就同步修改 API_PROXY_TARGET；浏览器直接跨域连接时还需匹配 CORS_ORIGINS。

## 5. 回归与故障定位

前端回归在 frontend 内执行 `npm test`、`npm run build`。后端安装开发依赖后执行 `python -m ruff check backend tests` 和 `python -m pytest tests/backend -q`。

数据库回归须由维护者配置 TEST_DATABASE_URL，指向独立空测试库，public 下没有业务表或迁移表，账号具备创建/删除临时 schema 权限。可选浏览器回归另装 Playwright Chromium 并设置 RUN_BROWSER_TESTS=1。缺少环境而跳过的项目不能算通过；不把演示库用作 pytest 数据库。完整测试入口见 [原演示清单](学生端交付验收与演示清单-20261015.md)。

| 现象 | 优先核对 |
| --- | --- |
| QUEUED 长时间不变或 SYSTEM_ERROR | worker、Redis、队列名、判题镜像和 Docker socket；保存提交 ID 后查看后端及 worker 日志 |
| ZIP 立即 422 | 外层文件名是否精确匹配当前登录人的学号、姓名及认领编号；清单字段是否完整 |
| INVALID / VIDEO | 缺视频示例的预期；完整包则检查 video.mp4 路径及实际文件 |
| 匿名材料处理失败 | 后端 ffmpeg 可用性、文件格式和材料身份线索；VALID 不等于教学内容质量合格 |
| 无法初始化或评分 | 是否自然提交截止、当前作品及材料有效、五人组正确，且评审截止尚未到达 |
| 聚合或发布被拒绝 | 当前作品是否收齐五份评分、教师分是否锁定、异常是否处理、HIGH 是否完成首次初评教师的最终复核 |
| 登录后请求失败 | 账号所属班级与角色、私有配置、实际后端地址；先查 HTTP 状态，不用反复登录代替定位 |

正常停止开发服务可用 `docker compose stop`，前端终端按 Ctrl+C。接手演示不使用删除卷命令重置数据。日志交接保留时间、commit、合成账号标识、作业/提交 ID、HTTP 状态及错误码，去掉密码、令牌和连接串。
