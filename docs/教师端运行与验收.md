# 教师端运行与验收

> 最新变更与实测结果见 [教师端审查修复与验收](教师端审查修复与验收.md)。
> 登录页不再预填账号密码；演示种子仅用于开发，生产环境拒绝运行。

## 1. 当前交付范围

教师端覆盖登录、课程总览、作业与 Rubric 创建、两个反向固定五人 Panel、作业发布、
评审任务初始化、教师评分、锁定、更正版本、异常复核、最终成绩发布，以及视频智能分析
的供应商中立扩展点。界面以电脑端键鼠操作为验收目标。

## 2. 本地启动

1. 启动 Docker Desktop。
2. 在仓库根目录复制 `.env.example` 为 `.env`，更换数据库密码和 `JWT_SECRET`。
3. 执行 `docker compose up --build`。
4. 执行 `docker compose exec backend python scripts/seed_demo.py`。
5. 在 `frontend/` 执行 `npm install` 和 `npm run dev`。
6. 打开 `http://localhost:5173/login`。

本地演示教师账号：`T001`；密码：`AlgoPeer2026!`。不得在公开部署中保留此密码。

## 3. 视频 AI 配置

视频 AI 默认关闭，人工播放与评分不依赖 AI。正式部署由管理员在服务器设置：

```text
AI_VIDEO_PROVIDER=<provider>
AI_VIDEO_API_KEY=<secret>
AI_VIDEO_BASE_URL=<optional-compatible-endpoint>
AI_VIDEO_MODEL=<video-capable-model>
AI_VIDEO_ENABLED=true
```

密钥不得通过浏览器提交、不得返回教师端、不得进入日志或数据库明文字段。不同服务商由
`VideoAnalysisProvider` 适配层接入。模型输出仅保存为建议与证据，教师明确确认后才可形成
独立的教师评分。

## 4. 合并前验证

```text
python -m pytest tests/backend -q
python -m ruff check backend tests
cd frontend
npm run build
```

浏览器冒烟脚本位于 `tests/frontend/teacher_ui_smoke.py`，使用确定性 API 响应检查电脑端
1440×1000 与 1024×768 两种视口、横向溢出和控制台错误。

## 5. 必查业务边界

* 非教师访问 `/api/teacher/*` 返回 403，未登录返回 401；
* 两个 Panel 必须方向相反，每组恰好五名来自评审班的不同学生；
* 只有 `VALID` 且材料检查为 `VALID` 的提交生成任务；
* 教师分保存后不可原地改写，锁定后更正必须新增版本并填写原因；
* 异常必须由教师明确确认或驳回，不能由算法自动处罚；
* 最终发布要求锁定教师分、跨班聚合分及无未处理异常；
* AI 评估表与教师分、最终分在数据库和权限上保持隔离。

## 6. 数据库及浏览器回归

设置 `TEST_DATABASE_URL` 到专用PostgreSQL实例，测试会新建独立schema并在结束后清理；
不要使用生产实例。未设置时数据库测试会标记跳过，不能据此宣称数据库测试已通过。

安装 `pip install -e "./backend[dev]" playwright` 和 `python -m playwright install chromium`，
设置 `RUN_BROWSER_TESTS=1`，运行 `python -m pytest tests/backend -q`。测试自动启动临时
FastAPI和Vite（前端端口15173），使用真实HTTP和数据库，结束后关闭测试服务。

旧的 `tests/frontend/teacher_e2e.py` 需要已启动的本地系统；密码从
`TEACHER_TEST_PASSWORD` 读取，账号可由 `TEACHER_TEST_ACCOUNT` 指定，默认T001。

## 7. 生产配置边界

使用独立文件 `docker compose -f docker-compose.production.yml up -d --build`，不要与开发
Compose叠加。配置数据库连接、独立JWT与内部服务密钥、前端HTTPS来源。生产文件不挂载源码，
不使用热重载，数据库不映射主机端口；后端仅绑定回环地址，由网关提供HTTPS访问。
前端静态文件、权限分离的数据库账号、备份及成员2/3集成仍需部署负责人配置与验收。
