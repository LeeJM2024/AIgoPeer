# 教师端审查修复与验收

日期：2026-09-29。审查基线：`teacher` 分支 `d1980f0`，核心实现 `508aef9`。
本次按教师端负责人职责开发，交付到 `teacher`，不合并 `develop/main`。

## 1. 交付范围与结论

教师端使用真实 FastAPI、PostgreSQL 事务和 Vue 页面，补齐名册、草稿编辑、评审进度、异常复核、
评分历史、发布检查、统计与导出。服务端和数据库共同维护成绩不可变性，测试覆盖真实数据库
和浏览器请求；不是用前端模拟数据实现教师业务。

这仍不是整个 AlgoPeer 的上线验收。成员2的上传/私有材料访问、成员3的聚合持久化与状态流转
尚未接入。浏览器测试通过明确标注的算法输出契约数据验证教师端，不声称验证了尚未实现的算法流程。

阅读依据：顶层01～05开发文档、组员1/2/3开发说明、教师交接与验收文档、PRODUCT.md、DESIGN.md。
学生页面和 `algorithm/` 算法代码未改写。公共认证、数据库完整性和部署配置的变更已同步接口文档。

## 2. 审查发现与修复

|级别|原问题、影响与复现方式|修复|
|---|---|---|
|P1|v1锁定后创建未锁定v2，发布仍选取“最新已锁定”的v1，跳过教师最新更正。|先取最新版本，再要求其已锁定；发布前检查与正式发布共用服务。|
|P1|并发首次评分/更正可竞争同一版本；发布与更正缺少共同锁。|统一作业→子记录锁顺序，连续版本数据库约束；更正增加 `expected_version`。|
|P1|发布后仍可评分、更正，页面和实际发布分可能分离。|API拒绝已发布写入，数据库冻结成绩及其评审/材料/聚合输入；页面只读。|
|P1|直接SQL可以在锁分时同时改主键、创建时间等未列入触发器的字段。|只允许首次改变 `locked_at`，其余字段逐项等价通过JSON行比较保护。|
|P1|最终发布允许零有效提交、缺失评审、旧聚合或错误归属聚合；结果未快照权重。|检查有效提交、五人完成、材料、运行与Panel归属、范围和时间；保存权重并校验公式。|
|P1|聚合/异常并发写入可能使发布前检查失效。|输入写入与发布共享作业行锁，发布后禁止输入修改；成员3事务必须按同一锁顺序接入。|
|P1|规则发布后直接删改Rubric会破坏历史分项解释。|发布后冻结量表与适用班级；权重、类型、提交截止及最终发布状态受保护。|
|P1|内部算法HTTP接口没有应用层认证。|独立服务凭证，未配置时关闭，教师JWT不能替代；移除浏览器开发代理。|
|P1|Docker未传JWT/AI环境变量，运行时可能继续用默认值。|开发和生产配置显式传递；production启动拒绝弱/默认JWT、共用服务密钥和示例库密码。|
|P1|登录无限尝试；JWT校验不要求过期声明。|数据库共享账号/IP限流；要求身份、角色、签发与过期声明；校验错误不回显输入。|
|P2|登录页预填演示密码；种子重复运行会覆盖用户已改的密码。|移除预填；种子不覆盖已有账号密码，production禁止执行演示种子。|
|P2|班级只读、草稿无法修改、异常无法从页面处理，缺少历史与导出。|新增实际API与页面、事务审计、发布阻塞原因和CSV导出。|
|P2|作业列表将提交和任务交叉连接后去重计数，数据增长时开销大。|改为按作业关联的独立计数，避免乘积中间结果。|

* `backend/app/api/routes/teacher_grades.py`：评分、更正、历史、复核、原子发布。
* `backend/app/api/routes/teacher_assignments.py`：草稿版本检查、Panel、初始化、延期与进度。
* `backend/app/api/routes/teacher_management.py`：班级与原子名册导入。
* `backend/app/api/routes/teacher_reports.py`：已发布成绩统计。
* `backend/alembic/versions/20260930_0003_teacher_integrity.py`：权重快照、数据库保护、限流表。

## 3. 教师可操作的功能

1. 创建和编辑班级，批量添加学生、移除未被业务引用的选课关系。已有学生密码不会被导入重置；
   名单冲突整批回滚，重复导入不重复选课，不泄露密码。
2. 创建期末/编程作业，配置班级、时区明确的截止时间、Rubric和权重。
   草稿可以编辑或删除；更换班级会清空评审组；旧页面不能覆盖新的编辑。
3. 配置两个反向五人Panel，发布时重验班级归属，禁止双重选课造成同班评审。
   初始化前检查材料结果；每个有效提交仍是五条固定跨班任务。
4. 查看评审完成数与具体缺失任务。可填写原因延长评审截止时间。
5. 录入评分、锁定最新版本、带原因更正；查看各版本分项、反馈、录入人和锁定状态。
6. 查看异常原始证据，确认或驳回并记录说明、操作人和时间；结论不会自动改教师分。
7. 查看发布阻塞清单，全部通过后原子发布；重复请求不会重复写入。
8. 查看成绩分布、按量表满分60%计算的及格率和平均分，导出带版本及权重的已发布成绩CSV。

## 4. 数据库与接口升级

新增迁移 `20260930_0003`，保留原有两次迁移，不修改已交付迁移历史。
执行 `alembic upgrade head`；先备份生产数据库。升降级已在隔离PostgreSQL中验证，
也验证了存在已发布成绩时升级后评分历史、总分和权重仍保留。

两项客户端必须同步的字段：

* 更正评分必须携带 `expected_version`。
* 编辑草稿必须携带原始 `expected_updated_at`。

错误统一为 `code/message/details`。`/internal/*` 新增 `X-Internal-Token`。
所有新增接口及前置条件见根目录 `04-接口文档.md`。

权重历史回填使用迁移时所属作业的权重；若旧部署曾通过SQL修改过已发布作业权重，需要在升级前
根据历史审计核对，迁移无法恢复未记录的历史配置。

## 5. 已执行的验证

本地Docker Desktop因自身 `dockerInference` 套接字错误启动失败。没有重置Docker或动原有卷。
改用EDB发布的PostgreSQL 16.15 Windows二进制，在 `storage/qa/postgres` 建立仅监听
`127.0.0.1:55432` 的隔离实例。每个测试使用随机私有schema，测试后删除，未访问业务库。

最终验证入口：

```text
python -m ruff check backend tests
cd frontend
npm run build
cd ..
# 设置 TEST_DATABASE_URL 为隔离PostgreSQL的连接串
# 设置 RUN_BROWSER_TESTS=1，并安装 python -m playwright install chromium
python -m pytest tests/backend -q
```

实测：**40 passed**，包括1440×1000与1024×768的两条真实浏览器链路。
一个依赖告警来自当前Starlette对httpx测试适配器的弃用提示，不是测试失败。

覆盖内容：正常发布、权重和公式、未锁定更正阻塞、评分并发、重复锁定/发布、材料无效、缺评分、
聚合缺失/过期、异常未处理、SQL历史不可变、第二条成绩写入失败的整批回滚、导入回滚/幂等、
学生越权、JWT异常、服务凭证、登录限流、时区/精度、草稿并发和删除、名册保护、迁移升降级。

浏览器实际完成登录→录分→锁分→更正→复核异常→发布→导出，还执行班级创建/导入和草稿创建/
编辑/删除。检查控制台、失败请求和横向溢出；截图和CSV在被忽略的 `storage/qa/`。

CI配置 `.github/workflows/teacher-checks.yml` 复用PostgreSQL16、构建与浏览器检查。
CI的远程执行结果须以GitHub运行记录为准，本地通过不能代替远程状态。
