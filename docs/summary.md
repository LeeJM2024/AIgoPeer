## 3. 登录、身份和教师工作台

### 3.1 从课程账号进入正确工作区

实现账号密码登录后，前端根据账号角色进入教师或学生工作区。教师身份来自后端认证结果，不由用户在登录表单中随意选择。

后端提供密码校验、JWT 生成与校验；前端保存登录状态并在会话失效后引导重新登录。后续还补强了令牌必需声明校验、登录限流和错误信息处理。

教师页面和教师接口分别有访问限制。即使学生绕过页面导航直接请求教师 API，也不应获得教师数据。教师身份校验是服务端执行的规则，而不是仅通过隐藏按钮实现。

### 3.2 工作台

总览页面把老师最常处理的事项放在前面：

- 当前进行中的作业数量。
- 待评分数量。
- 尚未完成的评审任务。
- 尚待处理的异常复核。
- 最近作业的提交与评审状态。

点击作业可进入具体管理页面。课程总览不是静态演示数字，而是读取后端返回的课程业务统计。

### 3.3 公共认证方面的补强

教师开发过程中对公共能力进行了必要扩展：密码采用加盐摘要，演示种子不应覆盖已有密码，生产环境不能运行演示种子，内部服务使用独立凭证，正式配置拒绝部分弱或默认密钥配置。

这些属于共享基础能力，不能描述成只影响教师端，也不能因此声称已经完成管理员后台、忘记密码、令牌吊销等整个账号生命周期。

## 4. 班级、学生和知识点管理

### 4.1 班级管理

教师可以新建班级、填写学期、修改班级名称与学期、选择班级查看学生。相同学期内同名班级受到约束，避免误建重复班级。

班级不仅用于展示，还会参与适用作业、学生选课和跨班评审资格的校验。

### 4.2 学生名册导入

教师可从表格复制学号、姓名和新账号所需的初始密码，将学生导入班级。

导入实现了几项重要保护：

| 情况 | 实际处理原则 |
| --- | --- |
| 新学生账号 | 检查必要信息和密码要求，再创建账号及选课关系 |
| 已存在同一学生 | 复用账号，不重置其已有密码 |
| 重复导入同一学生 | 不重复创建相同选课关系 |
| 学号相同但姓名或角色冲突 | 拒绝整批导入，提示核对身份 |
| 某一行处理失败 | 保证整批操作回滚，避免只导入前半部分 |
| 不同请求同时导入同一账号 | 使用数据库协调，减少账号与选课竞争 |

这部分将“贴一份名单”变成了可以重复操作、有冲突处理和结果统计的真实功能。

### 4.3 移出班级的保护

移出班级解除的是选课关系，不是直接删除学生账号。已经被评审组、作业提交或编程提交引用的关系不能随意移除，以免破坏评审资格和历史访问。

### 4.4 知识点目录

教师可以维护知识点编号、章节、名称和说明。学生认领目录使用这些数据，但认领页面与认领业务由成员 2 负责。

未被认领的条目允许修改或删除；已被认领的条目禁止修改删除，保留学生当时选择的依据。编辑提交还带原更新时间，防止旧页面覆盖其他操作已经保存的新内容。

## 5. 作业、评分标准与编程题管理

### 5.1 作业草稿与发布

教师可以建立期末微课作业或编程作业，设置名称、两个适用班级和截止时间。期末作业还包含评审截止时间与评分标准。

作业先保存为草稿。草稿支持编辑和删除；发布前检查配置是否齐全。发布后核心规则冻结，避免学生已经开始提交或评审时，教师又改变评分依据。

编辑草稿通过 `expected_updated_at` 检查版本。两人或两个窗口同时编辑时，后提交的旧页面不会静默覆盖新内容。修改适用班级会清除旧评审组配置，并要求重新配置。

### 5.2 评分标准

每项评分标准包含名称、满分、说明和顺序。教师可以添加和删除评分项。教师评分和学生评审使用对应作业的评分项，而不是在每个页面写死同一套字段。

前端限制仅是辅助，后端还校验评分项完整性、顺序、分数范围和精度。量表满分不强制永远等于 100；统计按满分比例计算，减少非 100 分量表的错误。

### 5.3 权重规则的历史变化

早期方案允许教师配置两类权重，要求非负且和为 1。后续收到逻辑更新说明后，期末作业改为固定教师 60%、评审 40%。

实现上的变化包括：取消表单中的权重编辑框，后端拒绝不合规定的期末权重，数据库增加约束，并处理旧未发布作业的权重。已经发布的历史成绩与权重快照保留，不能用新政策重算旧成绩。

因此，旧文档中的“教师自由配置权重”是历史阶段的描述，不是当前功能。

### 5.4 编程作业教师侧

教师可以配置：

- 题面、输入说明、输出说明。
- 时间与内存限制。
- 公开样例和隐藏测试用例。
- 各用例的输入及预期输出。

编程题草稿的题目与用例一起保存，发布后冻结。编程作业不使用期末微课的两组五人评审，因此发布时不再错误要求评审组。

教师可以查看当前版本的学生提交与测评状态，包括排队、测评中、通过、答案错误、超时、运行错误、编译错误和服务故障等。前端当前展示的重点是学生、班级、版本、状态和用例完成情况。

实际编译、执行、队列和容器判题属于成员 2 及运行环境的能力。你完成的是教师配置、发布与结果接入，不应把判题沙箱算法或执行器全部计为自己的实现。

## 6. 固定跨班五人评审配置与任务衔接

### 6.1 两个方向固定对应

本项目配置关系如下：

| 目标作品 | 评审人来自 | 人数 | 任务范围 |
| --- | --- | --- | --- |
| 1 班当前有效作品 | 2 班 | 固定五名不同学生 | 每人评阅 1 班全部当前有效作品 |
| 2 班当前有效作品 | 1 班 | 固定五名不同学生 | 每人评阅 2 班全部当前有效作品 |

两个方向需要同时合法。后端校验评审班、目标班、实际选课关系、重复人员和人数，避免仅靠前端勾选限制。

例如 1 班有 8 份符合条件的作品，则来自 2 班的五名评审人应产生 `8 × 5 = 40` 条任务。两个评审组独立计算，不把两班评审人的统计混在一起。

### 6.2 有效作品的含义

“上传过文件”不等于可进入评审。教师任务衔接需要检查作品是当前版本、提交状态有效、材料检查通过，以及作业处于允许操作的阶段。

材料不合格、尚未完成检查或已经被新版本替代的历史提交，不能被误选为当前正式评审对象。

### 6.3 初始化、进度和延期

教师在作业详情页触发分配。系统检查提交截止、材料状态和评审组配置，通过后生成对应任务并记录运行信息。重复操作要避免重复任务。

教师还能查看每位评审人的任务数、完成数和缺失任务。确需延期时，填写新的评审截止时间与原因；新时间必须符合延期要求。

当前缺评审的处理是等待补齐或按规则延期，没有实现静默减少人数、把四份当五份，或随意换一个人覆盖原评分。

## 7. 教师独立评分、锁分和更正

### 7.1 评分工作台

教师选择学生提交后，可以查看实名信息、材料状态、评审综合分、已有教师分和历史记录，再按评分项填写分数和反馈。

后端计算总分，使用 `Decimal` 与明确的两位小数舍入规则，避免只相信浏览器计算，也减少浮点误差。

“教师独立评分”在当前系统中意味着教师主动录入、单独保存、算法无权覆盖，不意味着教师首次录分前页面会强制隐藏全部评审综合分。后者若需要，应作为单独的盲评政策设计，不能凭“独立”两个字声称已经实现。

### 7.2 保存与锁定的区别

保存产生评分记录；锁定表示确认当前版本可作为发布依据。发布必须使用最新版本，并要求这个最新版本已经锁定。

例如：v1 已锁定，随后新增了 v2 但尚未锁定，此时不能继续偷偷采用 v1 发布。教师需要先核对并锁定 v2。

### 7.3 更正不覆盖历史

录入错误需要通过新增更正版本处理，不能原地改写或删除旧分数。更正需要原因，并传入预期的当前版本，避免并发覆盖。

```text
首次录分 → v1 保存 → 核对并锁定
发现错误 → 填写更正原因 → v2 保存 → 核对并锁定
发布成绩 → 引用确定的评分版本
```

历史页可查看分项、总分、反馈、录入人、时间、锁定情况与更正原因。数据库也保护历史，不能仅靠页面把输入框禁用来保证不可修改。

## 8. 作业材料和评分依据查看

### 8.1 材料查看

教师可以下载完整 ZIP，查看材料清单，预览支持的文本内容、播放视频或下载课件。文本预览对文件大小有界限，较大或不适合预览的内容走下载，不假装支持任意格式在线阅读。

访问材料经过教师权限校验。服务端会检查存储路径在允许目录内，ZIP 中的条目属于提交材料清单，并对异常条目大小、压缩比例和链接等情况作限制。

### 8.2 评审依据

评分工作台可以展开五名评审人的原始分项和评语，查看风险记录与处理结论。最终复核需要的教师分、评审综合分、原始评审和异常依据在教师工作区内均有入口。

教师使用实名数据是为了课程管理和复核；学生、评审人接口必须使用自己的数据范围或匿名内容，不能复用教师详情响应。

## 9. 成绩计算、发布、统计与导出

### 9.1 普通作品的计算

当前期末作业采用固定公式：

```text
最终成绩 = 0.60 × 最新已锁定教师评分 + 0.40 × 五人评审综合分
```

例如教师分 90，评审综合分 80，则最终成绩为 `54 + 32 = 86.00`。如果最新更正版本没锁定，不能退回采用旧版教师分来凑出结果。

### 9.2 高风险作品的计算

已经完成最终复核的高风险作品采用：

```text
最终成绩 = 已锁定的教师复核最终分
```

例如初评 90、综合分 80，但教师最终复核确定 88，则发布成绩是 88，不再按 60/40 得出 86。原始初评和综合分仍保留，用于解释和追踪。

成绩来源通过 `NORMAL_BLEND` 与 `TEACHER_FINAL_REVIEW` 区分，不能只看一列最终分而丢掉来源。

### 9.3 发布前检查

正式发布前会检查作业阶段、有效提交、材料状态、最新教师评分、五份评审、汇总记录及其归属、汇总是否过期、未处理异常和高风险复核等。

| 未满足的条件 | 为什么要阻止 |
| --- | --- |
| 无有效作品 | 不能把空发布误记为完成 |
| 最新教师分未锁定 | 教师还未确认当前正式评分 |
| 少于五份正式评审 | 不符合固定五人制度 |
| 汇总不存在或过期 | 最终成绩缺少有效评审依据 |
| 汇总来自错误作业或评审组 | 会把其他对象的数据用于当前成绩 |
| 分数超出评分标准范围 | 需要核查数据错误 |
| LOW/MEDIUM 未处理 | 缺少教师明确结论 |
| HIGH 未锁定复核最终分 | 不能走普通加权路径 |

检查结果在页面上表现为待办清单。正式发布会重新检查，不能只依赖前端曾经查到的“可以发布”。

### 9.4 原子发布与历史快照

同一作业的成绩在事务中发布。假设第二份成绩写入失败，不应留下第一份已经公开、其他份还未公开的半套结果。

最终成绩关联确定的教师评分记录、评审汇总记录、必要的最终复核记录、发布人、时间和权重快照。发布后的成绩和相关评分输入受到保护。重复发布请求返回既有结果，不重复插入。

### 9.5 统计和导出

教师可以查看提交与评审数量、已发布份数、平均分、满分、及格率和分布。及格依据是满分的 60%，分布也按得分比例分段。

CSV 导出包括学号、姓名、班级、提交编号、教师分、评审分、最终分、成绩来源、复核最终分及理由、教师评分版本、权重和发布时间。页面从统计接口读取已发布数据，再生成 CSV；不是另写了一个未经核对的“导出 API”。

导出还处理了中文编码、引号转义，以及可能被表格软件解释为公式的单元格内容。

## 10. 数据库、事务、并发和权限保护

### 10.1 已实施的保护

| 保护点 | 实现目的 |
| --- | --- |
| 教师接口角色校验 | 学生不能直接调用教师操作或读取教师材料 |
| 内部服务独立凭证 | 教师登录令牌不能直接替代算法内部调用凭证 |
| 作业父记录优先加锁 | 让评分、更正、发布与输入修改遵循一致顺序 |
| `expected_version` | 发现评分更正时的版本冲突 |
| `expected_updated_at` | 发现草稿或知识点的旧页面编辑冲突 |
| 不可变教师分历史 | 禁止覆盖或删除已经形成的评分记录 |
| 规则发布后冻结 | 避免更改评分标准破坏已有作业依据 |
| 发布后输入保护 | 避免成绩发布后相关输入又被改写 |
| 固定期末权重约束 | 防止接口绕过页面提交其他比例 |
| 复核教师身份约束 | 最终复核必须满足同一初评教师规则 |
| 审计记录 | 保存重要操作的操作者、对象及相关前后内容 |
| 整批事务 | 导入和发布失败时不留下部分成功的数据 |

数据库约束不是对任意超级管理员的绝对防护。这里完成的是项目应用及常规数据库写入路径的完整性保护；正式部署仍要配置实际运行账号权限。

### 10.2 数据升级也要保留历史

后续迁移补充教师分保护、固定权重、高风险来源和程序题规则等。对于已发布成绩，升级不能随意重写过去的分数与依据。历史迁移测试包含已发布数据保留及升降级检查，但不能由此推导所有生产备份与恢复场景都已经演练。

| `teacher_grades` | 独立教师评分及其版本 |
| `algorithm_runs`、`designated_review_aggregates` | 运行记录及评审综合结果 |
| `anomaly_records` | 异常依据和处理结论 |
| `teacher_final_reviews` | 高风险作品的教师最终复核 |
| `final_grades` | 正式发布结果及来源 |
| `audit_logs` | 重要业务操作记录 |
| `programming_problems`、`programming_test_cases` | 编程题及公开/隐藏用例 |

表格描述的是教师流程涉及的数据，不是把公共数据库设计与其他成员的表全部记作个人新建成果。
