## 3. 已实现范围

### 3.1 认证与权限

* 新增账号密码登录 `POST /api/auth/login`；
* 密码使用随机盐 scrypt 摘要，校验使用常量时间比较；
* 登录后签发带过期时间的 JWT；
* `/api/teacher/*` 全部使用教师角色依赖；
* 实测学生 Token 访问教师总览返回 403；
* 演示种子不再存储 `DEMO_ONLY` 明文占位，而是生成密码摘要。

主要文件：

* `backend/app/core/security.py`
* `backend/app/api/routes/auth.py`
* `backend/app/schemas/auth.py`

### 3.2 作业、Rubric 与跨班 Panel

* 查询班级、学生、作业列表和作业详情；
* 创建期末项目或编程作业；
* 校验两个不同班级、截止时间顺序、权重非负且和为 1；
* Rubric 项目必须有唯一顺序，分值必须为正；
* 一次配置两个方向相反的 Panel；
* 每个 Panel 必须是五名不同学生，且均属于指定评审班；
* 只有两个 Panel 均有效才能发布作业；
* 提交截止且材料检查无 `PENDING` 后才能初始化评审任务；
* 仅 `submissions.status='VALID'` 且材料检查为 `VALID` 的提交进入任务；
* 任务使用数据库唯一约束避免同一 Panel、提交、评审人的重复记录；
* 初始化记录算法运行名称、版本和输入哈希。

主要文件：`backend/app/api/routes/teacher_assignments.py`。

### 3.3 教师评分、锁分、更正和发布

* 评分请求必须包含全部 Rubric 项，每项恰好一次；
* 后端再次校验每项分数不超过 `max_score`；
* 教师总分由服务端使用 Decimal 计算；
* 首次评分写入版本 1；
* 锁分只允许锁定当前最新版本；
* 已锁定评分的更正必须新增更高版本并填写原因；
* 数据库触发器禁止 UPDATE 评分内容和 DELETE 历史评分；
* 异常可以由教师确认或驳回，并记录说明、处理人和时间；
* 发布最终成绩前要求最新教师分已锁定、聚合分存在且无未处理异常；
* 最终分在服务端按发布时权重计算，不由浏览器计算。

主要文件：

* `backend/app/api/routes/teacher_grades.py`
* `backend/app/services/teacher_grade_service.py`
* `backend/alembic/versions/20260929_0002_teacher_workflow.py`

### 3.4 教师电脑端界面

已实现路由：

|路径|用途|
|---|---|
|`/login`|账号登录|
|`/teacher`|课程和流程总览|
|`/teacher/assignments`|作业列表、新建作业和 Rubric|
|`/teacher/assignments/:id`|作业详情、Panel 配置、发布和任务初始化|
|`/teacher/assignments/:id/grading`|实名教师评分、锁定、更正和发布入口|
|`/teacher/ai-video`|查看视频 AI 服务是否安全配置|

界面使用稳定的左侧工作区导航、中文业务状态、明确的禁用状态和错误/空数据提示。没有把它
设计成大屏 Demo，也没有使用花哨的 AI 渐变或玻璃效果。产品与视觉约束记录在根目录
`PRODUCT.md` 和 `DESIGN.md`。

### 3.5 视频 AI 扩展点

本次没有虚构一个“已经会自动看视频打分”的实现。实际完成的是：

* 服务器端环境变量：服务商、Base URL、API Key、模型、启用状态；
* 教师端只读取配置状态，永远不能读取完整 API Key；
* `VideoAnalysisProvider` 供应商中立协议；
* `video_analysis_runs` 保存模型、输入哈希、Rubric 快照、任务状态和错误；
* `ai_rubric_assessments` 保存建议分、置信度、理由和时间点证据；
* AI 表与 `teacher_grades`、`final_grades` 分离；
* 数据库注释明确 AI 结果仅供建议，不得自动成为教师分。

尚未接入任何真实模型，也尚未实现视频上传、转码、语音转写、抽帧和供应商文件清理任务。

## 7. 当前已知缺口与风险

以下内容应由独立审查者重点确认。此列表是主动披露，不代表可以忽略。

### P0：完整系统合并前必须处理

1. **成员 3 聚合尚未持久化。** 当前内部聚合接口返回计算结果，但公共骨架尚未把结果写入
   `designated_review_aggregates`。没有聚合记录时最终成绩发布会按设计拒绝。
2. **状态流转尚缺聚合完成入口。** 当前任务初始化进入 `REVIEWER_GRADING`，但需要成员 3/
   公共后端在评审完成后更新 `AGGREGATING → TEACHER_GRADING`。
3. **学生上传和视频存储未实现。** 这属于成员 2 模块；教师评分页目前只保留证据区，尚无真实
   视频播放器、签名下载地址、转码或对象存储。
4. **`/internal/*` 目前依赖网络隔离，没有应用层服务认证。** 如果后端端口直接暴露公网，内部
   初始化/聚合接口可能被调用。部署前必须加服务凭证或在网关严格阻断。

### P1：正式上线前必须加强

1. 登录没有频率限制、失败次数锁定、密码修改/重置和管理员建号流程；
2. 当前 scrypt 参数固定在代码中，尚无密码算法升级/重哈希机制；
3. API 错误结构尚未全部统一为正式文档中的 `code/message/details`；
4. 作业列表、学生列表和评分工作区没有分页，大班数据需要分页和索引压测；
5. 缺少数据库级接口集成测试自动化，当前数据库联调步骤是实际执行但未纳入 pytest；
6. Playwright Python 包需要单独安装并执行 `playwright install chromium`；
7. Docker 后端命令包含 `--reload`，适合开发，不应作为生产启动命令；
8. JWT 只有访问 Token，没有刷新、吊销和密钥轮换机制；
9. 操作审计目前重点覆盖锁分与更正，作业发布、Panel 变更和最终发布也应补齐统一审计；
10. AI 表目前只是逻辑隔离，尚未创建专用数据库账号并验证其无权写教师分。

### P2：教师端后续功能

1. 班级和学生目前只能查询，尚无导入、创建、转班和停用；
2. 题库、知识点和测试数据配置尚未实现；
3. 草稿作业尚无编辑/删除接口；
4. 异常复核后端已实现，但没有单独的异常处理页面；
5. 统计目前只有摘要计数，没有成绩分布、通过率图表和导出；
6. 没有批量评分、自动保存草稿和键盘快捷评分；
7. AI 视频页只显示配置状态，尚无真实模型适配器、成本/配额控制和重试队列。
