# 学习分析

教师在“学习分析”中按全部班级或指定班级查看课程过程数据：谁已经提交、学生在哪些题目反复尝试、常见错误是什么，以及哪些知识点需要补充讲解。

## 提交与编程统计

| 指标 | 计算口径 | 阅读方式 |
| --- | --- | --- |
| 已提交人数 | 至少提交过一次的学生人数 | 与参与名单、未提交人数一起看完成情况 |
| 判题人数 | 至少获得一次 AC / WA / TLE / RE / CE 的学生人数 | 排队、运行中与系统故障单独展示 |
| 曾通过人数 | 历史中至少一次 AC 的学生人数 | 反映曾经完成题目的学生范围 |
| 当前通过人数 | 当前有效代码结果为 AC 的人数 | 区分曾经通过与当前版本状态 |
| AC 率 | 曾通过人数 ÷ 判题人数 | 分母为实际获得正常判题结果的学生 |
| 描述性难度 | 1 − AC 率 | 描述当前课程样本的完成表现 |
| 常见错误 | 历次有效判题中的 WA / TLE / RE / CE 次数 | 同一学生多次尝试会贡献多次错误记录 |
| 平均尝试次数 | 总提交次数 ÷ 提交过的学生人数 | 帮助观察反复调试的程度 |

没有正常判题样本时，AC 率和难度显示为空。系统故障单列处理。教师可继续打开作业中的提交历史，核对代码版本、错误详情与编译反馈。

## 知识点观察掌握率

每个关联知识点汇集学生在相关作业中的可用结果：

- 编程题采用当前有效判题：AC 记为 1，WA / TLE / RE / CE 记为 0。
- 期末微课采用已发布成绩除以作业满分。
- 算法分析、证明、开放问答展示作答情况和答案，属于完成型活动。

对有效的“学生—作业”结果等权平均，得到知识点观察掌握率。历史版本保留供查阅，计算时使用当前版本，避免重复计入。未提交、尚未完成判题、系统故障或未发布成绩的记录等待形成有效结果。

多知识点作业的整体结果会关联到各个对应知识点；这项统计反映已观察到的课程作业表现。结合样本数、覆盖人数和具体答案，可以更准确地决定下一步教学安排。

## 在线作答与期末微课

在线作答题显示提交人数、当前答案与历次版本。教师可用这些答案了解学生的推导、证明和表达方式。

期末微课显示当前有效作品、已发布成绩和平均分。学生认领的知识点与教师关联的知识点共同参与学习证据汇总。

## AI 教学建议

在当前班级范围中打开“AI 教学建议”，可围绕常见错误、复习顺序或下一次练习安排提问。系统将当前统计汇总发送给教师配置的文字模型，模型结合这些证据给出建议。

建议上下文使用统计数据，个人身份、学生源码和未发布的个人成绩留在课程系统中。具体配置、配额与对话记录见[AI 辅助特色](AI辅助特色.md)。
