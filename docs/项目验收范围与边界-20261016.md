课程功能验收覆盖三条主线：日常编程、期末提交、跨班评审至成绩反馈。原七个闭环加上新引入的注册入班环节，整理为以下八个闭环；编号变化不表示新增八项开发需求。

| 编号 | 闭环 | 闭合范围 |
| --- | --- | --- |
| C01 | 注册/已有账号 → 登录 → 教师入班 | 账号身份合法，入班关系正确，既有密码保留，学生具备正确课程可见性 |
| C02 | 教师准备与发布 → 学生收到作业 | 课程规则、两类作业配置、适用班级、发布时间状态及学生入口一致 |
| C03 | 编程提交 → 队列与实际判题 → 结果 | 页面、API、Redis、worker 和隔离容器衔接，正确区分代码结果与服务故障 |
| C04 | 编程多版提交 → 本人历史 → 当前结果与草稿恢复 | 当前和旧版数据独立，记录可追溯，草稿按账号/作业隔离 |
| C05 | 知识点认领 → ZIP 上传 → 材料/匿名化检查 → 修正重传 | 合法材料形成当前有效作品，不合格材料有明确反馈并被排除出正式评审 |
| C06 | 期末多版本 → 当前恢复与历史 → 截止只读 | 当前记录及各版检查保留，状态读取和上传限制一致 |
| C07 | 教师初始化 → 双向指定任务 → 匿名材料 → 五人评分 | 固定五人、跨班、本人任务、合法计时和一次性评分均成立 |
| C08 | 完整评分 → 聚合/异常 → 教师锁分与复核 → 发布 → 本人反馈/教师导出 | 成绩依据合法、完整且可追溯，学生只得到允许展示的本人结果 |

以下条目是上述闭环的必查边界及支撑能力；不能只验收八条正常路径而遗漏对应异常、越权和历史保护。

## 3. C01：注册、登录、班级与身份边界

- 学生可以自助注册；学号和姓名按接口规范校验并去首尾空白，密码长度与全空白限制正确，合法密码的原有首尾空格不被擅自修改。
- 注册角色固定为 `STUDENT`；不能通过附加字段注册教师、选择班级、指定其他身份或直接获得课程权限。
- 已存在学号不能覆盖已有姓名、角色、密码；并发重复注册不能产生两个账号。
- 注册成功不自动颁发登录令牌，不自动建立选课关系；学生经正常登录进入学生工作区。
- 新注册且未入班的学生可正常登录并看到明确空状态，不能读取未被授权的课程作业或任务。
- 教师按同一学号和姓名将已注册学生加入班级，复用账号且保留原密码；教师直接导入新账号也属于既有入班途径。
- 班级名称/学期及名单约束、重复导入、身份冲突、整批失败回滚、并发导入结果正确；移出班级只解除允许解除的关系，不删除账号或破坏已有引用。
- 正确/错误凭据、未登录、会话过期、退出及重新登录均有明确结果；角色来自服务端身份，不能由页面选项或客户端字段提升。
- 登录后进入正确角色工作区；会话失效和返回地址不得使用户陷入无法进入工作区的重定向循环。
- 登录与注册的独立持久化限流、错误码和等待提示遵守现有接口规范，不能因重启或混用计数失效。
- 对外响应和错误信息不泄露密码、摘要、完整令牌或服务密钥；教师账号不提供公开注册。

## 4. C02：课程准备、两类作业发布与学生接收边界

- 教师班级/名单、知识点目录及工作台统计具有真实数据来源，页面与后端一致；空数据和失败状态可区分。
- 知识点的新增、编辑、删除遵守唯一性和引用保护；已被认领的条目不能被改写或删除，保留历史依据。
- 草稿支持允许的创建、编辑和删除；旧页面版本冲突不能静默覆盖新内容，班级变化后的 Panel 配置不得被错误沿用。
- `PROGRAMMING` 与 `FINAL_PROJECT` 的必填配置、入口和后续流程不同，不得互相套用发布条件。
- 编程题具备题面、输入输出说明、资源限制及公开/隐藏用例后发布，不要求期末五人 Panel。
- 期末作业的 Rubric、提交/评审截止和双向 Panel 配置完整；人数不足、重复、班级关系或选课关系不合法时不能发布。
- Rubric 使用后端下发的项目、满分和顺序；支持合法的非 100 分量表，不能在评分或统计中写死总满分为 100。
- 期末权重固定为教师 60%、评审 40%，不接受客户端自行配置其他比例。
- 发布前学生不可读取草稿；发布后仅适用班级的学生可见，作业类型、截止时间、当前阶段及本人提交摘要正确。
- 作业发布后的核心规则、题目/用例及相关历史依据遵守冻结约束；编程作业不进入期末互评和加权发布流程。
- 教师查询到的提交情况与学生本人摘要一致；学生列表不带入其他学生记录或教师内部数据。

## 5. C03：编程提交与实际判题边界

- 学生只能在适用的非草稿编程作业读取公开题面和公开样例；隐藏用例不下发。
- 仅开放阶段且未过服务器截止时间允许提交；错误类型、未发布、外班、教师误用学生接口及非法输入均被后端拒绝。
- 当前承诺语言为 `cpp17`，源码编码、大小及参数按现有契约约束，不将多语言支持纳入默认验收要求。
- 数据库记录、Redis 入队、worker 消费和实际隔离容器执行形成真实链路，不能用静态状态或模拟响应替代实际判题可用性结论。
- 排队、执行中、AC、WA、CE、RE、TLE 含义准确；Docker 等待超时按执行超时处理，普通连接故障不得伪装成学生代码错误。
- Docker/Redis/worker 等基础设施失败明确为 `SYSTEM_ERROR`，遵守既有重试与终态规则，不自动作为学生扣分或算法风险依据。
- 实际判题遵守题目资源限制及既有网络、进程、文件系统隔离边界；Web 后端和前端不直接获得执行学生代码的 Docker 权限。
- 结果只返回允许的本人汇总；CE 的受限编译信息按契约展示，隐藏输入、标准/实际输出、逐用例内容和其他学生源码不泄露。
- 输出比较、用例完成数、耗时等结果含义与后端实现一致；不将“通过构建”或“worker 运行中”写成实际判题已通过。

## 6. C04：编程历史、草稿及恢复边界

- 多次提交保留历史，版本和当前标记正确；列表仅包含本人数据，按最新版本在前排序，前端每页 5 条。
- API 分页上下界、空列表、超出最后一页和缺少可见作业等情况遵守接口契约；不能以客户端指定学生 ID 扩大查询范围。
- 旧版结果只读，无旧源码读取、删除、修改或重新判题入口；选择旧记录不替换编辑器、当前结果或当前轮询。
- 当前结果通过服务端记录恢复，不依赖遗留的本地提交 ID；旧账号缓存不能恢复为新账号的结果。
- 未提交源码草稿仅存本浏览器，按学生和作业隔离；草稿恢复、清除、存储受限的反馈准确，历史接口不承担草稿恢复。
- 判题轮询停止、失败、重载或手动刷新后仍反映对应提交；截止后允许读取本人已有结果和历史，不能借此绕过提交限制。

## 7. C05：期末认领、上传、材料检查与匿名化边界

- 学生只能读取适用作业的知识点与本人认领，认领关系和界面一致；每名学生每份作业只认领一项，重复认领被拒绝。本版本允许不同学生认领同一知识点。
- 未认领、文件名与学号/姓名/认领编号不匹配、非 ZIP、超限或清单非法时不能形成合法提交；文件名及上限遵守接口文档。
- 上传清单中的 PPTX、MP4、README、源码、至少三个例题及至少三组测试文件，与 ZIP 内声明路径和实际条目一致；页码引用不得超出真实 PPT 页数。
- ZIP 中危险相对/绝对路径、越界条目、符号链接、重复条目、异常压缩比及超出既有限额等情况不能进入正常材料链路。
- `PENDING/VALID/INVALID/RETURNED` 按实际结果展示；硬性缺失项和建议项分开，检查失败不伪装成通过。
- PPT 建议页数及视频时长尚未自动核验的提示按现有规则处理；不将建议项一律升级为硬性失败，也不把“完整性通过”当成内容正确、质量合格或自动评分通过。
- 提交归档文件可以按要求带提交人身份；发给评审人的只能是单独生成的匿名派生包。
- 派生包只包含允许的声明材料，文件名使用通用名称，支持格式的身份元数据经过处理；已知姓名/学号线索或处理失败不能被静默放行。
- 视频匿名化包含真实可执行的处理链路；教师原始视频访问与评审匿名视频不能混为同一个下载权限。
- 图片可见文字、视频画面和音频中的身份信息不能宣称已可靠自动识别；材料的人工匿名核对是内容边界的一部分。
- 不合格、检查未完成、匿名包失败或非当前版本不得进入正式有效作品评审集合；修改材料后重新上传产生新版本，不原地覆盖旧检查依据。
- 上传失败和后台检查失败有可辨认反馈；失败不能破坏原已保存版本或留下被错误当作有效作品的记录。

## 8. C06：期末当前版本、历史、刷新及截止边界

- 同一学生/作业的当前版本唯一；当前版本、时间、提交状态、材料检查状态和是否可上传由服务端数据支持。
- 页面重载和手动刷新能恢复当前版本及检查；不需要重新选择 ZIP 或重新上传才能查看已有结果。
- 当前检查短时轮询后明确停止或失败提示，手动刷新只读取状态，不隐式重新执行后台检查。
- 本人历史按版本倒序、前端每页 5 条；旧版的原检查结果独立保留，不用提交的 `SUPERSEDED` 标记代替材料检查结果。
- 历史缺少检查或时间的旧数据如实显示缺失，不伪造为检查中或通过。
- 选择旧版不替换当前版本、不改变上传表单、不干扰当前轮询；新上传后历史回到第一页，已选旧详情保持独立。
- 旧版 `PENDING` 只提供手动读取结果；历史不增加下载、删除、回滚或重新检查功能。
- 列表/详情失败、翻页失败、切换作业、离开页面及响应先后顺序变化时，不把旧请求的数据写进新对象。
- 上传开始前及收包完成入库时均使用服务端规则检查阶段和截止；跨截止拒绝须保留原当前记录，并清理该失败上传的新文件。
- 截止或进入后续评审、评分、已发布阶段后，仍允许合法读取本人已有提交及历史，不能继续上传；前端禁用不能替代服务端限制。

## 9. C07：固定五人跨班任务与匿名评分边界

- 两个方向均必须成立：1 班作品由 2 班指定五人评，2 班作品由 1 班指定五人评；不是随机分配、自助领取或任意浏览作品库。
- 每名指定评审人承担目标班全部当前有效作品，每份作品正常应有恰好五份正式评分；两组各自统计，不能混合归属。
- 教师在合法阶段触发初始化，提交截止、当前有效作品、检查状态及 Panel 条件均满足后才产生正式任务；重复初始化不能制造重复任务。
- 评审入口依据实际有效任务显示，只有 Panel 成员资格仍不够；任务归属、对方班在籍关系、本人非作者且不在目标班、作业阶段均由后端校验。
- 评审列表、详情和材料只能来自本人任务；不能通过改任务 ID、班级、学生或作品参数越权。
- 原提交 ZIP、作者姓名/学号/ID、教师分、聚合分、其他评审记录及异常证据不下发评审端；作者查分时也不暴露评审人身份。
- 匿名包准备完毕且下载成功后才记录服务端开始时间并允许评分；失败或未准备完成不得伪造开始时间，客户端自报时间不能覆盖它。
- Rubric 必须完整且每项一次，分数在下发满分范围内，评语非空；非法额外身份或任务分配字段被拒绝。
- 仅允许阶段与评审截止内提交；并发/重复提交只有一次成功，提交后不提供修改评分或重新领取入口。
- 教师可查看真实评审进度与缺失任务；合法延期记录新截止和理由，不通过默减人数、静默换人或将四份当五份解决缺评审。

## 10. C08：聚合、教师评分、发布与反馈边界

### 10.1 算法与运行记录（成员 3 主责）

- 同一 Panel 全部有效作品达到所需五份正式评分后才进入正式聚合；缺评分、不完整/重复 Rubric、错误归属或不合法输入不能被补零后当成完整集合。
- 两个 Panel 分别进行鲁棒 Bayesian MAP-EM 聚合、画像和异常识别；逐项/总分、风险、回退说明及运行记录与对应输入一致。
- 画像资格按每位评审人不同作品数计算，至少三份；不能把同一作品的多个 Rubric 项当成多个作品。`learned=True` 还要求成功收敛且画像被接受。
- 小样本使用逐项中位数及先验画像；五人每维度一致只豁免适用作品的区间宽 HIGH，不能顺带消除真实极端或行为风险。
- 未收敛时恢复约定回退结果和先验；后端记录 FAILED，不保存为正式成功聚合、画像或异常，不以半成品推进发布。
- 缺材料、缺评分、异常评分、教师分与聚合分显著不同均属于必须覆盖的业务边界；风险只提供证据和复核要求，不自动处分学生。
- 教师原始分不参与算法改写、删除或自动降权；聚合结果、教师分及复核最终分分别保留。
- 复用结果必须匹配作业、Panel、版本、输入摘要和配置；不同版本/配置不能错误复用，失败及落库异常不留下部分正式结果。
- 旧运行、被替代异常及审计记录按既有策略保留；已发布作业和已锁定复核最终分的历史不被新聚合静默覆盖。
- 回退区间和后验可用性按真实含义解释，不把占位数值或先验区间当成已学习模型的可信结论。

### 10.2 教师评分、材料与历史（成员 1 主责）

- 教师能读取受权的原始 ZIP、清单内材料、支持的文本/视频及五人原始分/评语/异常依据；不支持或过大的预览走明确下载途径，不承诺所有格式在线预览。
- 原始材料下载仍须角色、路径、清单和 ZIP 安全校验；不能因“教师可实名查看”放开任意文件访问。
- 教师逐项录入完整有效分数及反馈，服务端精确计算总分，正确显示零分、空分和非 100 分量表。
- 保存与锁定是不同状态；发布使用最新版本且该版本已锁定。新更正未锁时不能退回旧锁定版凑齐发布条件。
- 更正通过新增版本和原因记录完成，原记录不能被 UPDATE/DELETE 覆盖；并发保存、更正、锁分、发布遵守既有冲突保护。
- “独立评分”表示教师主动录入并独立保存、算法无权改写；当前没有要求初评前对教师强制隐藏全部评审综合分，不能额外承诺盲评流程。

### 10.3 异常处理、发布与统计（成员 1/3 主责）

- 普通作品使用固定 `0.60 × 最新已锁定教师初评分 + 0.40 × 有效五人聚合分`。
- 实际 LOW/MEDIUM 异常须教师明确确认或驳回；HIGH 必须由首次评分的同一教师，在最新初评锁定后录入并锁定复核最终分与理由。
- HIGH 的最终成绩直接取锁定复核最终分，不再混入 60/40；初评、聚合、最终复核、处理原因及来源均可追溯。
- 空作品、材料无效、教师分未锁、缺正式评分、聚合缺失/过期/归属错误、未处理异常或缺必要复核时不能发布。
- 发布前检查与正式发布的判断一致，正式发布仍重新核验，不能依赖页面此前查到的状态。
- 同一作业发布保持原子性；失败不形成部分已公开结果，重复请求不产生重复成绩；正式结果保存其版本、权重、聚合和复核快照。
- 已发布结果及关联输入遵守历史保护；历史迁移不能静默按新规则重算旧成绩。
- 教师统计和 CSV 明细来自真实已发布数据，数量、平均分、分布、满分、及格比例及成绩来源正确；普通加权和复核分来源可区分。
- CSV 字符编码、引号和公式型文本处理遵守已交付行为，不将前端导出描述成不存在的独立后端导出接口。

### 10.4 学生反馈（成员 2 主责）

- 发布前学生不能取得最终成绩、教师原始分、聚合分或评语；不存在本人结果与尚未发布等情况不伪造结果。
- 发布后只返回认证学生自己的最终总分、发布时间、Rubric 说明、匿名评语和教师反馈。
- Rubric 说明不等于展示维度具体得分；教师原始分、聚合分、评审人身份、异常和内部复核证据不进入学生响应。
- 改作业或提交参数不能取得他人成绩；另一个有自己成绩的学生取得的是其本人结果。

## 11. 新版前端及所有闭环共用的边界

- 验收对象包括当前蓝白主题、校院标识及新版工作台，不能以旧版页面代替本轮界面范围。
- 登录、注册、教师、学生和评审页面的标识、角色导航、按钮及跳转一致；认证状态和评审资格变化同步到入口。
- 学生工作台的课程数、已提交数、已发布项目数、待办和状态来自本人真实数据，不由插画或静态演示文本伪造。
- 默认展开项、其余列表、搜索、类型筛选、无匹配及清除筛选的结果完整、不漏项；主列表与展开卡片按设计不重复计入，辅助推荐卡不当作新增作业记录。
- 教师总览待办、作业搜索/状态筛选、真实材料与评分并排等新版入口保留原业务能力，不能因布局调整遗漏权限、截止或复核提示。
- 算法插画及归并演算属于课程展示，不能当成题目隐藏测试或学生判题结果；演算的暂停、步进、重播、离屏/页面隐藏及减少动态效果等既有交互应符合记录的行为。
- 主要入口、表单、错误、加载、空状态、只读及禁用状态清楚；窄屏与横竖屏下不遮挡关键内容，键盘与焦点等已交付基础可用性不退化。不扩大为全设备或完整无障碍认证。
- 会话切换、路由切换、刷新、响应先后顺序及重复请求不能泄露或混淆其他账号、其他作业和旧版本数据。
- 页面隐藏按钮之外，直接 API、下载和常规数据库写入路径的权限与历史约束同样生效；界面成功提示不能覆盖服务端实际失败。
- 密钥、JWT、密码、数据库连接凭据及真实学生资料不能进入公开交付、截图或错误响应；正式脱敏边界与教师受权实名操作区分。

## 12. 环境、证据与生产交付的范围区分

### 12.1 为课程功能验收必须明确的前提

- 前后端可连接真实数据库和 Redis；编程链路具备可用 worker 与判题镜像，匿名视频处理具备可用 ffmpeg，上传与派生材料在当前运行环境可读取。
- 实际页面、实际接口、真实判题容器、真实视频处理、纯函数、组件替身和数据库测试的覆盖范围分别说明；任何一种通过不能冒充其他类型通过。
- 版本、时间、业务阶段、截止、现有数据归属明确；已截止的旧 QA 作业不能被擅自改规则以假装仍开放。
- 全部使用合成数据并保留既有 QA 容器、卷、资料与历史；清理、重置、重算、公开上传或向他人发送资料不因本范围文件自动获得授权。
- pytest 只使用专用空测试库；当前 `search_path` 含 `public` 的已知夹具隔离问题仍需主负责人处理，不能将已有 QA/业务库当回归目标，也不能记为已修复。

### 12.2 只有声明“生产交付完成”时才一并验收的事项

- 前端静态托管、HTTPS/API 转发、独立认证及数据库权限、内部服务隔离。
- 生产判题 worker/镜像及权限配置，后端/worker 的数据库、队列及存储关系正确。
- 上传、派生材料和数据库的持久化、备份/恢复、升级/重启后的可用性及部署冷构建。
- 生产密钥、来源配置和演示种子的保护，以及部署负责人已承诺的运维交付项。

当前生产 Compose 不包含完整前端托管、判题服务和上传文件持久化配置；不能仅以该文件存在或本地 Docker 启动成功声称生产交付已完成。具体上线标准由主负责人/部署负责人另行确定，不能默认全部转给成员 2。

## 13. 明确不纳入当前默认功能验收的事项

| 事项 | 本轮范围界定 |
| --- | --- |
| 视频 AI 自动理解、转写、抽帧和自动打分 | 当前只有状态/协议扩展点；已交付状态入口的真实性与密钥隔离可查，不要求真实模型能力，不以此阻断 MVP |
| 完整账号生命周期 | 不新增找回密码、管理员后台、令牌吊销或自主修改身份/班级功能 |
| 多语言、重判与代码相似性 | 不新增 C++17 之外语言、相似性检测、旧源码读取或重判流程 |
| 历史材料操作 | 不新增历史下载、删除、回滚、重新检查或历史评分返修入口 |
| 评审制度变化 | 不新增随机/自助领取、四人代替五人、任意替换评审人或学生自助回避 |
| 算法与学术结论 | 不承诺准确识别所有恶意/串通，不自动纪律处罚，不因验收方便调整风险政策，不新增论文级性能保证 |
| 额外产品能力 | 不新增消息推送、移动 App、个性化推荐、任意文件预览或服务端大班分页 |
| 非功能认证与容量指标 | 不凭空新增并发量、响应时间 SLA、渗透测试认证、全设备兼容或完整无障碍认证指标；若已有正式外部要求，由主负责人补充确认 |

“未纳入”不豁免已交付能力的正常错误处理、授权与数据正确性，也不把新界面已有的基础响应式行为排除出去。

## 14. 设计方案前仍需明确的事项

- 主负责人确认最终采用的代码基线及是否将已在 main 的前端改版同步回 develop；本地运行版本与团队集成分支当前不同。
- 主负责人确认最终签收目标是课程功能演示，还是同时包含生产部署；两种完成声明的边界不同。
- 各模块负责人确认验收中需要其共同签收的跨模块部分，特别是初始化、算法风险、教师复核及成绩来源，不由成员 2 代替签收算法或教师政策。
- 公共测试隔离问题的处理状态和被允许使用的测试环境由主负责人确认；本文件不设计修复方案。

本文不替代最终验收结论。后续方案应从这些边界提取覆盖项，并另行记录执行结果；当前不安排也不启动验收执行。
